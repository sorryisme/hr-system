# 시드 데이터 — 팀 구성 확대 (총괄·복지행정팀·간호재활팀·요양1~6팀)

- **일자:** 2026-07-28
- **대상 앱:** `apps/api`

---

## 1. 배경

기존 `prisma/seed.ts`는 `1층팀`/`2층팀` 2개 팀, 직원 9명(1~9번)만 시드했다.
실제 조직 구조(총괄/복지행정팀/간호재활팀/요양1~6팀, 총 9개 팀)를 반영하고, 팀별 인원을
3명씩(총 27명)으로 구성하도록 요청받아 `prisma/seed.ts`를 수정했다.

## 2. 변경 내용 (`apps/api/prisma/seed.ts`)

- **팀 목록:** `1층팀`/`2층팀` 제거 → `총괄`, `복지행정팀`, `간호재활팀`, `요양1팀`~`요양6팀`(9개)
- **직원 27명(9개 팀 × 3명), id 1~27:**
  - 총괄(3): 김평온(DIRECTOR/ADMIN), 박든든(OFFICE_MANAGER/ADMIN), 이살핌(SOCIAL_WORKER/STAFF) — 기존 결재 권한자 3명을 총괄 팀으로 편입
  - 요양1팀(3): 최정성·정보람·한슬기(기존 4~6번, 팀 재배치)
  - 요양2팀(3): 오다정·강마루·윤새봄(기존 7~9번)
  - 복지행정팀(3): 임소망·서다솜(SOCIAL_WORKER), 노한결(CLERK) — 신규 10~12번
  - 간호재활팀(3): 문슬아(NURSE)·배건강(PHYSICAL_THERAPIST)·신바름(OCCUPATIONAL_THERAPIST) — 신규 13~15번
  - 요양3~6팀(각 3명, 총 12명): 신규 16~27번, CAREGIVER/NURSE_AIDE 혼합
- **모바일 등록 PIN:** 신규 종사자(10~27번)에게도 기존 3~9번과 동일한 방식으로 6자리 코드 부여
- **버그 수정:** `employee.upsert`의 `update` 절에 로그인 계정 정보만 있고 `teamId`가 빠져 있어,
  이미 DB에 존재하는 직원(1~9번)은 재시드해도 팀 재배정이 반영되지 않는 문제를 발견 → `update`에
  `teamId: emp.teamId` 추가

## 3. 검증 (로컬 DB)

- `pnpm run db:seed` 실행 ✅ (approval_request/schedule_entry 기존 데이터로 해당 픽스처는 스킵, 팀·직원 upsert는 정상 수행)
- 재실행 전: `teamId` 미반영 버그로 기존 4~9번 직원이 예전 `1층팀`/`2층팀`에 남아있는 것 확인
- `teamId` update 반영 수정 후 재실행 → 직원 27명 전원이 의도한 팀에 배정됨을 쿼리로 확인
  - 팀별 인원 3명씩(9개 팀 × 3명 = 27명) 정합 확인
- 더 이상 참조되지 않는 예전 `1층팀`/`2층팀` 팀 레코드는 (직원·근무기준 참조 없음을 확인 후) 로컬 DB에서 삭제해 정리
- `tsc --noEmit` — `seed.ts` 관련 타입 에러 없음(기존 무관 테스트 파일 에러만 존재)

## 4. 참고

- 연차 잔여(`leaveBalance`)·근무표 픽스처(`shiftEmployees`, id 4~9)는 이번 변경 범위 밖이라 그대로 유지
  (신규 직원 10~27번은 연차 잔여·근무표 셀 데이터가 없음)
