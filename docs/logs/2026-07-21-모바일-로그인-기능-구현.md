# 모바일 로그인(기기 등록) 기능 구현

- 근거 문서: `docs/plan/dev_plan_0720.md` §2.2 Phase 0(C-13), §3.8-7(기기 분실), §7 N-10
- 범위: `apps/mobile` — 종사자 모바일 웹뷰의 최초 1회 기기 등록 → 자동 로그인 플로우

## 구현 내용

- `apps/mobile/src/features/device-auth/` 신설
  - `types.ts`, `domain.ts`: 화면 상태, 코드 정제/완성 판별(숫자 6자리)
  - `mock-data.ts`, `device-auth-service.ts`: 관리자 발급 코드 검증 Mock. 백엔드 인증 도메인 및 Orval 연동 시 `POST /api/devices/register` 호출로 교체 예정(CLAUDE.md: Orval 연동 전까지 백엔드 미호출 원칙 준수)
  - `device-storage.ts`: 기기 등록 여부(불리언)만 저장. 세션 토큰이 아니므로 CLAUDE.md의 "토큰 localStorage 저장 금지"와 무관하다고 판단 — 실제 인증 토큰은 백엔드 연동 시 httpOnly 쿠키로 관리한다.
  - `use-device-auth.ts`, `device-auth-page.tsx`: 코드 입력 → 검증 → 완료 화면 2단계 위저드(N-5, N-7)
  - `components/code-entry-screen.tsx`, `components/welcome-screen.tsx`
  - `device-auth-gate.tsx`: 앱 전체를 감싸 미등록 시 등록 화면을, 등록 후에는 기존 화면(휴가 신청 등)을 보여줌
- `apps/mobile/src/components/shared/mobile-shell.tsx`에 `DeviceAuthGate` 적용
- `apps/mobile/src/components/ui/input.tsx`: shadcn CLI로 신규 추가(`npx shadcn add input`)

## 검증

- `tsc -b`, `oxlint` 통과(기존 shadcn 생성 파일의 사전 경고 2건 외 신규 이슈 없음)
- Chrome 확장(브라우저 자동화)이 연결되지 않아 실제 화면 렌더링은 육안으로 확인하지 못함 — 코드/타입 검증만 완료된 상태
