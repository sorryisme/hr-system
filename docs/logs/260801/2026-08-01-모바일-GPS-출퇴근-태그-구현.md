# 모바일 GPS 출퇴근 태그 구현 (Phase 3 — B-2, MVP)

## 배경

`feat15/mobile-attendance` 브랜치. docs/plan Phase 3(출퇴근)는 GPS 원터치 태그 외에 미태그 워크플로우(C-14)·수동태그 결재 폴백(MANUAL_TAG)·실근무시간 정산까지 포함하는 큰 단위라, 이번엔 **GPS 원터치 출퇴근(B-2)만** 범위로 잡았다(사용자 확인). `AttendanceRecord`/`Facility` GPS 필드가 이미 스키마에 있어 **DB 마이그레이션 없이** 구현 가능했다.

## 변경 사항

### 백엔드 (`apps/api/src/attendance/`, leave 모듈과 동일 패턴)

- `GET /attendance/today` — 열린(퇴근 미처리) 기록이 있으면 그 근무를, 없으면 오늘 배정된 근무(ScheduleEntry)를 조회해 상태(CLOCKED_IN/OUT)·근무 요약·관리자 호출번호 반환
- `POST /attendance/clock-in`, `POST /attendance/clock-out` — `{lat,lng}` → Haversine으로 `facility.gpsLat/gpsLng/gpsRadiusM` 반경 검증 → `AttendanceRecord` upsert. workDate는 태그 시점의 달력일 — 야간근무는 시작일에 태그하므로 별도 보정 없이 귀속일이 자연히 시작일이 된다(퇴근은 workDate가 아니라 "열린 기록"으로 찾는다)
- 에러 코드: `FACILITY_GPS_NOT_CONFIGURED`, `OUT_OF_RANGE`, `ALREADY_CLOCKED_IN`, `ALREADY_TAGGED_TODAY`, `NOT_CLOCKED_IN`
- DTO 클래스명 충돌 주의: approvals/roster에 이미 `ShiftTypeSummaryDto`/`RosterShiftTypeSummaryDto`가 있어(과거 커밋 161eb38 — nestjs/swagger가 클래스명을 스키마 키로 써서 동명 DTO가 서로 덮어쓴 사고 이력) 이번 DTO는 `AttendanceShiftSummaryDto`로 접두어를 붙였다. openapi.json 재생성 후 스키마명 충돌 없음을 확인함
- `app.module.ts`에 `AttendanceModule` 등록
- `seed.ts`: 샘플요양원(id=1) upsert에 GPS 좌표(서울시청 인근, 임의값)·반경 100m·관리자 호출번호(031-283-3211) 추가, 로컬 DB에 재시드(마이그레이션 아님, 데이터만)

### 모바일 (`apps/mobile/src/features/attendance/`)

- `orval.config.ts`에 `attendance` 태그 추가 → `useGetToday`/`useClockIn`/`useClockOut` 생성
- `use-geolocation.ts` — `navigator.geolocation` 3초 타임아웃 래퍼, 권한거부/타임아웃 실패 원인을 쉬운 말로 변환(N-9)
- `domain.ts` — "오후 9시 52분" 시각 포맷, "오늘은 야간 근무입니다 · 17:50~다음날 09:00" 문장 조립
- `use-attendance.ts` — 오늘 상태 조회 + 태그 뮤테이션 + 진동 피드백(N-6) + 결과 화면 상태
- `components/attendance-button-screen.tsx` — 화면 70%+ 대형 버튼(출근하기/퇴근하기 자동 전환)
- `components/attendance-result-screen.tsx` — 성공(초록 전체화면)/실패(빨강 + 원인 문구 + 관리자 호출 `tel:` 버튼)
- `attendance-home-page.tsx`를 자리표시자에서 실제 구현으로 교체
