# 근무표 셀 편집(클릭/드래그) — 백엔드·프론트 구현

- 브랜치: `feat14/roster-cell-edit`
- 근거: `docs/plan/dev_plan_0720.md` §4.8 "셀 클릭 → 근무유형 선택 팝오버. 드래그로 다중 셀 일괄 입력."

## 배경

`updateEntries`(셀 다건 편집) API는 feat13에서 이미 구현되어 있었으나, 프론트에는 셀을
직접 편집하는 UI가 없었다(프리셋 적용 우클릭 메뉴만 존재). 이번 작업은 §4.8의 나머지
입력 방식(셀 클릭/드래그)을 프론트에 연결하는 것이 목적이다.

## 백엔드

- `GET /rosters/shift-types` 추가(`roster:read`) — 셀 편집 팝오버의 근무유형 선택지.
  `ShiftTypeSummaryDto { code, label, cellLabel }`를 시설 기준으로 반환.
- `updateEntries`는 기존 그대로 사용(프리셋 적용과 달리 셀 보호 원칙 없이 항상 덮어씀 —
  관리자의 명시적 직접 입력이므로).
- DTO 작성 시 `cellLabel`을 `@ApiProperty({ nullable: true })`만 쓰면 Orval이
  `{ [key: string]: unknown } | null`로 잘못 생성하는 기존 이슈(ShiftPatternItemDto에도
  동일하게 남아있음, 이번 범위 밖)를 이번 신규 DTO에서는 `type: String`을 명시해 회피.

## 프론트

- `apps/web/src/components/ui/popover.tsx`: shadcn CLI로 추가 후, `PopoverContent`가
  `anchor`(base-ui의 가상/외부 앵커 엘리먼트)를 전달받을 수 있도록 `Pick`에 추가.
  트리거 없이 임의의 DOM 엘리먼트에 팝오버를 앵커링하기 위함(셀 클릭·드래그는
  고정된 트리거 버튼이 없으므로).
- `apps/web/src/features/roster/cell-edit-popover.tsx`(신규): 선택된 셀 목록에
  근무유형을 일괄 적용하는 팝오버. `useListShiftTypes` + `useUpdateEntries` 사용.
- `apps/web/src/features/roster/schedule-grid.tsx`: 셀 클릭/드래그 선택 로직 추가.
  - 드래그 중 사각형은 `ref`(진행 중 값, 매 mouseenter마다 갱신되지만 리렌더를
    유발하지 않음)와 `state`(미리보기 렌더용)로 분리.
  - `window`의 `mouseup`을 구독해 드래그가 그리드 밖에서 끝나도 선택이 확정되도록 함.
  - 선택 사각형은 팀 구분과 무관하게 전체 직원 순서(`flatEmployees`) 기준 행 인덱스 ×
    날짜 열 인덱스로 계산 — 팀 헤더 행이 중간에 끼어 있어도 좌표 계산에 영향 없음.

## 검증

- `tsc --noEmit`, `eslint`(API) / `oxlint`(웹), `vite build` 통과.
- API 단위 테스트 99건 통과(기존 스위트, 이번 변경으로 깨진 것 없음).
- 브라우저 실기동 확인(claude-in-chrome): 셀 클릭 → 팝오버 오픈 → "휴무" 선택 →
  `PATCH /rosters/:id/entries` 호출 → 그리드 셀이 "휴"로 갱신되고 새로고침 후에도
  유지됨을 확인. 드래그 다중 선택은 이 세션의 자동화 클릭 도구가 간헐적으로 좌표를
  누락하는 문제가 있어(실제 마우스 물리 이벤트가 아닌 합성 이벤트의 한계), 단일 셀
  클릭 경로로 전체 흐름(mousedown→mouseup→팝오버→적용→API→재조회)을 확인했고
  드래그 사각형 계산 로직은 동일 코드 경로를 코드 리뷰로 재확인함.

## 버그 수정: 클릭·드래그 시 팝오버 즉시 닫힘

최초 구현 후 사용자가 "클릭하거나 드래그 시 팝오버가 바로 사라진다"고 보고. 원인 분석:

- `schedule-grid.tsx`는 `window`의 네이티브 `mouseup` 이벤트 안에서 `setPopover(...)`를
  호출해 팝오버를 연다. base-ui `Popover`는 열리는 즉시(`useDismiss`) `document`에
  outside-press 감지 리스너(`click`/`pointerdown`/`mousedown` 등, capture 단계)를 붙인다.
- 문제는 **같은 클릭의 뒤이어 발생하는 네이티브 `click` 이벤트**다. 브라우저는
  `mousedown → mouseup → click` 순서로 이벤트를 발생시키는데, 우리가 `mouseup` 핸들러
  안에서 동기적으로 팝오버를 열면 React 커밋 + 이펙트(리스너 등록)가 뒤따르는 `click`
  이벤트가 도착하기 전에 끝나버린다. 그 결과 방금 붙은 outside-press 리스너가 자신을
  열게 만든 바로 그 `click`을 "팝오버 바깥 클릭"으로 오인해 즉시 닫아버림
  (`useDismiss.js`의 `outsidePressEvent: 'intentional'` 모드는 `click` 타입만 판정에
  사용 — mousedown/mouseup 자체는 무시하도록 설계되어 있어 드래그는 원래 안전해야
  하지만, 드래그 종료 시 mouseup 지점 아래 엘리먼트를 대상으로 한 `click`도 동일하게
  뒤따라 발생해 같은 문제가 재현됨).
- 최초 브라우저 검증(위 §검증) 때는 `mousedown`/`mouseup`만 합성 디스패치했고 `click`은
  포함하지 않아 이 문제를 놓쳤다.

**수정**: `handleWindowMouseUp` 안에서 `setPopover(...)`를 `setTimeout(fn, 0)`으로 한 틱
지연시켜, 이 클릭을 마무리하는 `click` 이벤트가 완전히 전파된 뒤에 팝오버가 열리도록
했다(`schedule-grid.tsx`). outside-press 리스너가 등록되는 시점을 그 뒤로 미뤄 자기
자신을 여는 클릭을 감지하지 못하게 하는 방식 — 이후 진짜 바깥 클릭에는 정상적으로
반응해 닫힌다(회귀 확인 완료).

재검증(claude-in-chrome, `mousedown`+`mouseup`+`click`을 모두 디스패치):
- 셀 클릭 → 팝오버가 열린 채 유지됨(수정 전에는 즉시 닫힘) 확인.
- 이어서 페이지의 다른 지점을 동일하게 클릭 → 팝오버가 정상적으로 닫힘(outside-press
  자체는 계속 동작) 확인.
- API 단위 테스트 99건 재실행, 변경 없음 확인.

## 리뷰 반영: DTO 클래스명 충돌로 결재 API 스키마 손상

코드 리뷰에서 `apps/api/src/roster/dto/shift-type-summary.dto.ts`의 `ShiftTypeSummaryDto`가
`apps/approvals/dto/request-list.dto.ts`에 이미 있던 동명 클래스(`{ id, label }`, 결재
`desiredShift` 필드가 참조)와 충돌한다는 지적을 받음.

- 검증: `nestjs/swagger`는 클래스명을 컴포넌트 스키마 키로 쓰므로, 신규 근무표 DTO가
  나중에 스캔되며 `components/schemas/ShiftTypeSummaryDto`를 `{ code, label, cellLabel }`로
  덮어씀. 실제 `openapi.json`에서 확인: `RequestListItemDto.desiredShift` /
  `RequestDetailDto.desiredShift`가 잘못된 스키마를 참조하게 되고, Orval 생성 타입에서
  `id` 필드가 사라짐(런타임 응답은 원래대로 `{ id, label }`이므로 문서·타입과 실제
  응답이 불일치). 프론트 소비 코드(`request-list.tsx`, `request-detail-panel.tsx`)는
  `desiredShift.label`만 참조해 당장 런타임 오류는 없었으나, 계약 손상 자체가 문제.
- 조치: 근무표 쪽 DTO를 `RosterShiftTypeSummaryDto`로 개명(`shift-type-summary.dto.ts`,
  `roster.service.ts`, `roster.controller.ts`), `openapi:export` + `generate:api` 재실행.
  재생성 결과 `ShiftTypeSummaryDto`는 다시 결재 도메인의 `{ id, label }`로 복원되고,
  근무표용은 `rosterShiftTypeSummaryDto.ts`로 별도 생성됨을 `openapi.json`/Orval 산출물
  직접 확인. 양쪽 앱 `tsc --noEmit` 통과.
