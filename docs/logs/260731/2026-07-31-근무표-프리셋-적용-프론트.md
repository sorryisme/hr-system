# 근무표 프리셋 적용 — 관리자 웹 화면

- **일자:** 2026-07-31
- **선행:** `docs/logs/260731/2026-07-31-근무표-프리셋-적용.md` (백엔드 API)
- **대상 앱:** `apps/web`

---

## 1. 배경

백엔드에 `POST /rosters/:id/apply-preset`(프리셋 적용)와 `GET /rosters/shift-pattern-presets`
(프리셋 목록 조회, 이번 슬라이스에서 추가)가 갖춰졌으나, 관리자 웹 근무표 화면(§4.8 "직원 행
우클릭 → 프리셋 적용")에는 이를 호출하는 UI가 없었다. 기존 `ScheduleGrid`는 조회 전용이었고
(셀 수동 편집 UI도 아직 없음), Orval 생성 클라이언트에도 두 엔드포인트가 반영되지 않은 상태였다.

## 2. 변경 사항

**백엔드 — 프리셋 목록 조회 추가** (이번 슬라이스에서 신규)
- `GET /rosters/shift-pattern-presets`(`roster:read`) — `RosterService.listPresets()`.
  프리셋 헤더 + 조×일차별 근무유형 코드/셀 라벨을 함께 내려 다이얼로그에서 패턴 미리보기 없이도
  조 수·주기를 바로 활용할 수 있게 함. DTO: `ShiftPatternPresetSummaryDto`/`ShiftPatternItemDto`.
- 시드에 데모용 프리셋 1건 추가: "주야비 3조 2교대"(`cycleDays=6, teamCount=3`,
  A조 주·주·야·야·휴·휴 / B조 휴·휴·주·주·야·야 / C조 야·야·휴·휴·주·주) — §4.6 표기 그대로.
- `apps/api/openapi.json` 재생성(`openapi:export`)해 apply-preset·shift-pattern-presets 반영.

**프론트 — Orval 재생성**
- `pnpm --filter web generate:api` 실행 → `useApplyPreset`/`useListPresets` 훅과
  `ApplyPresetDto`/`ApplyPresetResultDto`/`ShiftPatternPresetSummaryDto` 등 모델 생성.

**프론트 — 프리셋 적용 UI**
- shadcn CLI로 `context-menu` 컴포넌트 신규 추가(`components/ui/context-menu.tsx`).
- `ScheduleGrid`: 직원 행 이름 셀을 `ContextMenu`로 감싸 우클릭 시 "프리셋 적용…" 메뉴 노출.
  근무표가 `DRAFT`/`COMPLETED`일 때만 노출(§4.8 — `CLOSED`/`CLOSING_APPROVAL`은 편집 자체가
  불가하므로 메뉴도 숨김). 우클릭 대상은 `<td>` 내부 콘텐츠에만 걸어 `<tr>`/`<table>` 구조를
  깨지 않도록 함.
- 신규 `apply-preset-dialog.tsx`: 프리셋 선택 → 조(팀) 선택 → 시작일/종료일(기본값 = 근무표
  해당 월 1일~말일) 입력 → 적용. 성공 시 적용 건수와 건너뛴(승인/수동 편집 보호) 건수를 안내하고
  근무표 쿼리를 무효화해 그리드를 갱신한다.

## 3. 트러블슈팅 — Select 컴포넌트 사용 중 브라우저 행 프리즈

로컬 브라우저(Claude in Chrome)로 실제 화면에서 검증하던 중, "조" 선택 콤보박스를 열면
렌더러가 응답 없음 상태(스크린샷·접근성 트리 조회가 전부 타임아웃)로 빠지는 문제를 발견했다.

- **원인:** `SelectTrigger`에 `disabled={!preset}`만 걸어두고 `SelectContent`는 조건부로
  빈 배열(`preset && [...]`)을 렌더링했다. 프리셋 미선택 시 항목이 0개인 상태로 Select가
  열리면 base-ui(`@base-ui/react/select`)의 `alignItemWithTrigger` 위치 계산이 정상 종료되지
  못하고 멈추는 것으로 추정된다(라이브러리 자체 이슈로 프로젝트 코드에서 재현 조건만 제거).
- **해결:** `preset`이 없을 때는 `<Select>`를 아예 마운트하지 않고 동일한 시각 스타일의
  정적 placeholder `<div>`로 대체했다. `preset`이 확정된 뒤에만 실제 `<Select>`가 마운트되므로
  항목 0개 상태 자체가 발생하지 않는다.
- 별개로 `SelectValue`가 기본적으로 원시 `value`(프리셋 UUID·조 번호 문자열)를 그대로
  표시한다는 점도 확인해, `children` 렌더 함수로 라벨을 명시적으로 매핑하도록 수정했다
  (base-ui `Select.Value`는 Radix와 달리 선택된 `Item`의 자식을 자동으로 가져오지 않음).

## 4. 검증

- `tsc -b`(apps/web) ✅, `oxlint` ✅ (기존 shadcn 프리미티브의 사전 존재 fast-refresh 경고만 있음, 무관)
- 로컬 API(`start:dev`)·웹(`vite dev`) 기동 후 브라우저로 golden path 확인:
  로그인 상태 유지 → 근무표(2026년 7월, DRAFT) → 직원 행 우클릭 → 프리셋 적용 → 패턴/조/기간
  선택 → 적용 → "29건 적용 완료 · 승인/수동 편집 셀 2건은 건너뛰었습니다" 확인 → 그리드 갱신
  후 프리셋 패턴 반영 + 기존 보호 셀(시간 조정·오후반차 override) 원형 유지 확인.

## 5. 남은 한계

- 조 배정 연속성(§4.6 A-2)은 백엔드가 이전 PRESET 셀을 근거로 자동 판단하므로, 프론트는
  시작일을 그대로 전달할 뿐 "이어붙임 여부"를 화면에 별도로 안내하지 않는다.
- 현재는 직원 1명 단위로만 적용 가능(대상 행 우클릭 = 해당 직원). 팀 단위 일괄 적용은 범위 밖.
- 셀 수동 편집(팝오버로 근무유형 선택, 드래그 다중 선택) UI는 이번 슬라이스에도 포함되지
  않았다 — `PATCH /rosters/:id/entries`는 백엔드에 이미 있으나 프론트 미착수.
