# 모바일 로그인(기기 등록) 프론트엔드 실연동 + 라우트 가드

- 근거 문서: `docs/plan/dev_plan_0720.md` §2.2 Phase 0(C-13), §7 N-10
- 선행 작업: `docs/logs/2026-07-21-모바일-로그인-기능-구현.md`(프론트 Mock),
  `docs/logs/2026-07-21-모바일-로그인-백엔드-api-구현.md`(백엔드 `POST /api/devices/register`)
- 범위: `apps/mobile` — Mock을 실제 API 호출로 교체하고, 미로그인 상태에서 다른 화면 접근 시
  `/login`으로 리다이렉트하는 라우트 가드 도입

## 구현 내용

### Orval 연동 신설(`apps/mobile`)

- CLAUDE.md Architecture: "Orval 연동은 각 프론트에 실제 API 클라이언트가 필요해지는 시점에
  구성한다" — 이번이 그 시점이라 `apps/web`과 동일 패턴으로 신설했다.
- `orval.config.ts`: 입력은 `apps/api/openapi.json`(공용). `apps/web`과 달리 `filters.tags:
  ['auth', 'devices']`로 좁혀 결재(`requests`) 관련 타입·훅은 생성하지 않는다 — 모바일은
  아직 그 도메인을 쓰지 않는다.
- `src/api/mutator.ts`: `apps/web`의 동일 파일과 같은 패턴(httpOnly 쿠키 `credentials:
  'include'`, 401 시 `/login`으로 전체 리로드). `/api/auth/*`, `/api/devices/*`는 리로드
  대상에서 제외 — 로그인 확인(`auth/me`)과 등록 실패(`devices/register`)는 화면에서 직접
  처리한다.
- `.env.example`: `VITE_API_URL` 추가(`apps/web`과 동일 컨벤션, 시크릿 아님).
- `package.json`: `generate:api` 스크립트 + `orval` devDependency 추가(이미 `apps/web`에서
  쓰던 동일 버전 재사용 — 레지스트리 신규 취득 없음).

### 인증 상태 관리 신설 — `apps/mobile/src/features/auth/session.ts`

- `apps/web/src/features/auth/session.ts`와 동일한 패턴: 모듈 스코프 캐시 + `GET /auth/me`
  1회 확인. `requireAuth`(보호 라우트 `beforeLoad`)와 `redirectIfAuthenticated`(`/login`
  전용 `beforeLoad`) 제공.
- 기기 등록(모바일)과 이메일 로그인(관리자 웹)이 동일한 `SessionUserDto`/`cs_access_token`
  쿠키·`/auth/me`를 공유하므로 백엔드 추가 작업 없이 그대로 재사용된다.

### 라우트 가드 도입 — 클라이언트 게이트(`DeviceAuthGate`) 제거, 라우터 `beforeLoad`로 대체

- `routes/login.tsx` 신설: `beforeLoad: redirectIfAuthenticated`, `component:
  DeviceAuthPage`.
- `routes/index.tsx`: `beforeLoad: requireAuth` 추가 — 미로그인 상태로 접근하면 `/login`으로
  리다이렉트된다(이번 작업의 핵심 요구사항).
- `components/shared/mobile-shell.tsx`: 기존에는 `DeviceAuthGate`가 앱 전체를 감싸 클라이언트
  상태(localStorage 불리언)로 등록 화면을 가로막았다. 이 방식은 관리자가 기기를 해제해도
  로컬 플래그가 그대로 남아 있으면 오탐(계속 로그인된 것처럼 보임)이 발생할 수 있어, 라우트
  단위 `beforeLoad`(항상 서버 세션을 확인)로 교체했다. `device-auth-gate.tsx`는 삭제.

### Mock → 실제 API 교체

- `features/device-auth/device-auth-service.ts`, `mock-data.ts` 삭제(더는 쓰이지 않음).
- `use-device-auth.ts`: `verifyDeviceCode` Mock 대신 Orval이 생성한 `useRegister`
  (`POST /devices/register`) 훅을 사용. 성공 시 `setSessionUser`로 세션 캐시를 채우고
  welcome 화면으로 전환, 실패 시 서버가 내려주는 한국어 메시지(`INVALID_CODE` 등)를 그대로
  노출한다(N-6 이중 피드백 — 진동 포함, 기존 로직 유지).
- `device-storage.ts`: 기기 등록 여부 불리언 대신 기기 식별자(UUID, `crypto.randomUUID()`)만
  저장하도록 재작성. 로그인 여부의 단일 소스는 서버 세션(`/auth/me`)이고, 이 값은 최초
  등록 요청의 `deviceUid` 파라미터로만 쓰인다.
- `components/welcome-screen.tsx`: `MOCK_EMPLOYEE_NAME` 대신 등록 응답의 실제
  `employee.name`을 표시.
- `components/code-entry-screen.tsx`: 요청 진행 중(`isSubmitting`) 입력·버튼 비활성화 및
  "등록 중…" 표시 추가(중복 제출 방지).

## 검증

- `apps/mobile`: `tsc -b`, `oxlint` 통과(기존 shadcn 파일 경고 2건 외 신규 이슈 없음).
- `apps/api`: 회귀 없음 확인(`jest` 43개 전체 통과) — 백엔드는 변경하지 않음.
- **로컬 DB(MySQL) + 실행 중인 API·모바일 dev 서버로 브라우저 전체 플로우를 실제로
  검증했다**(Playwright MCP). 검증 중 5173/5174/3000 포트에 이미 떠 있던 프로세스는 사용자의
  기존 세션으로 보여 건드리지 않고, 3001/5175 포트에 격리된 인스턴스를 별도로 띄워 테스트한
  뒤 종료했다(main.ts CORS에 5175를 임시 추가했다가 테스트 후 원복 — 커밋 diff에는 남지 않음).
  - 미로그인 상태로 `/` 접근 → `/login`으로 리다이렉트 확인.
  - 잘못된 코드(`999999`) 제출 → 서버 메시지("등록 코드가 맞지 않아요…") 그대로 노출 확인.
  - 유효 코드(`555555`, 정보람) 제출 → welcome 화면에 실제 이름 표시 → "시작하기" → `/`로
    이동 후 보호된 홈 화면 정상 렌더 확인.
  - 전체 새로고침(모듈 캐시 초기화) 후에도 재로그인 없이 유지됨을 확인(N-10).
  - 로그인 상태에서 `/login` 직접 접근 → `/`로 리다이렉트 확인.
  - DB에서 해당 기기의 `revoked_at`을 직접 설정(관리자 원격 로그아웃 시뮬레이션) →
    다음 요청에서 즉시 `/login`으로 튕겨나감을 확인(엣지 7 대응이 실제로 동작함을 검증).

## 미결 사항

- 관리자가 코드를 발급하는 화면(관리자 웹)과 기기 원격 로그아웃 화면은 여전히 미구현
  (백엔드 로그 참고).
- 로그아웃 버튼 등 모바일 자체 UI는 이번 범위 밖 — 기기가 곧 로그인 수단이라는 설계상
  일상적인 로그아웃 동작은 정의돼 있지 않다(필요 시 별도 결정 필요).
