# 모바일 연차 신청 — 월 선택 기능 추가

## 배경

앞서(`docs/logs/260805/2026-08-05-근무표-미생성월-연차신청-차단.md`) 당월 근무표 미생성 시 신청을 막는 작업을 했는데, 그 시점 모바일 날짜 선택 화면은 항상 `new Date()` 기준 "이번 달"만 보여줬다(월 선택 UI 자체가 없었음). 다음 달 이후 미리 연차를 신청하고 싶어도 방법이 없어, 날짜 선택 화면에 월 이동을 추가해 달라는 요청을 받았다.

## 범위 결정

아래는 별도 확인 없이 합리적 기본값으로 정한 사항이라, 다르게 쓰고 싶으면 알려주면 조정 가능하다.

- **선택 가능 범위**: 이번 달 ~ 향후 2개월(과거 달 탐색은 제외 — 사후 신청은 기존처럼 "이번 달 안의 지난 날짜"만 지원).
- **근무표 미생성 달 처리**: 월 선택 자체는 막지 않고, 그 달을 보는 동안 날짜 선택 화면에 안내 문구를 띄우고 달력을 비활성화 + "다음" 버튼을 막는다.
- **월 전환 UI**: 달력 헤더 좌우 화살표(추가 화면·바텀시트 없이 같은 화면에서 전환 — 시니어 친화 원칙 "화면당 1과업" 유지).

## 백엔드(apps/api)

이전 작업에서 추가한 `GET /leave/roster-status`가 "당월"만 조회했는데, 이제 화면이 여러 달을 오갈 수 있어 조회 대상 월을 쿼리 파라미터로 받도록 확장했다.

- `dto/roster-status.dto.ts`: `RosterStatusQueryDto` 신규 추가 — `yearMonth?: string`(`YYYY-MM`, `roster-query.dto.ts`와 동일한 정규식 검증, 생략 가능).
- `leave.service.ts`: `getCurrentMonthRosterStatus(facilityId)` → `getRosterStatus(facilityId, yearMonth = 당월)`로 일반화.
- `leave.controller.ts`: `GET /leave/roster-status`가 `@Query() query: RosterStatusQueryDto`를 받아 `yearMonth` 생략 시 당월로 폴백.
- 테스트(`leave.service.spec.ts`): `getRosterStatus` 신규 describe 블록 2건(생략 시 당월 조회, 지정 시 해당 월 조회 + 미생성 케이스) 추가. `PrismaMock`에 `roster.findUnique` 목 추가.

## 프론트엔드(apps/mobile)

### `domain.ts`

- `MAX_MONTH_OFFSET = 2` 상수, `viewedMonth(monthOffset, now)` 헬퍼(0=이번 달 … +2개월, 연도 넘어가는 12월 케이스 포함) 추가.
- `rangeText(days, month)` → `rangeText(days, year, month)`로 시그니처 변경 — 월이 고정이 아니게 되면서 확인 화면에 "2026년 7월 21~22일"처럼 연도까지 표기.

### `use-leave-request.ts`

- `State`에 `monthOffset: number`(기본 0) 추가. `resetWizard`(홈으로/신청 시작 시)에서 0으로 리셋.
- `prevMonth()`/`nextMonth()` 액션 추가 — `[0, MAX_MONTH_OFFSET]` 범위로 제한하고, 달이 바뀌면 `selectedDays`(일자만 들고 있어 다른 달과 섞이면 안 됨)와 `blockedMessage`를 초기화.
- `submit()`이 `now` 대신 `viewedMonth(state.monthOffset)`로 계산한 연/월로 `targetDates`를 만들도록 변경.

### `components/calendar.tsx`

- `CalendarGrid`에 이전/다음 달 화살표 버튼(달력 헤더, "{year}년 {month}월" 좌우) + `monthDisabled` prop 추가. `monthDisabled`면 날짜 버튼 클릭을 막고(`disabled`) 그리드를 흐리게(`opacity-40`) 표시.

### `components/date-select-screen.tsx`

- `rosterStatus: 'exists' | 'missing' | 'loading' | 'unknown'`, `canGoPrevMonth`/`canGoNextMonth`, `onPrevMonth`/`onNextMonth` prop 추가.
- `rosterStatus === 'missing'`이면 "이 달 근무표가 아직 준비되지 않아 신청할 수 없어요" 안내 카드를 띄우고 "다음" 버튼을 비활성화. `loading`/`unknown`(조회 실패)일 때는 막지 않고 제출 시점 서버 검증(이전 작업에서 추가한 `ROSTER_NOT_FOUND`)에 맡긴다 — 매 월 전환마다 로딩 스피너로 화면이 깜빡이는 걸 피하기 위한 선택.

### `components/confirm-screen.tsx`

- `year` prop 추가, `rangeText` 호출에 반영.

### `leave-request-page.tsx`

- 이전 작업에서 홈 화면 진입을 통째로 막던 로직(`applyBlocked`, 홈 화면 레벨의 당월 `roster-status` 조회)을 제거 — 이제 월을 여러 개 고를 수 있으므로 특정 달만 근무표가 없다고 신청 전체를 막을 이유가 없다. 대신 `LeaveRequestScreens`에서 현재 보고 있는 달(`state.monthOffset`)에 대해서만 `useGetRosterStatus({ yearMonth })`를 호출(`step1`일 때만 `enabled`)하고, 그 결과를 `DateSelectScreen`에 내려준다.
- `todayOfMonth`는 `monthOffset === 0`(이번 달을 보는 중)일 때만 실제 오늘 날짜, 그 외 달에서는 0으로 넘겨 "지난 날" 스타일링·로직이 미래 달에서 오작동하지 않게 했다(`calendar.tsx`/`domain.ts`의 `hasPastSelected`/`hasDeadlineWarning`는 수정 없이 그대로 재사용 가능).
- `components/home-screen.tsx`: 이전 작업에서 추가했던 `applyBlocked` 분기를 제거해 원상 복구(신청 진입 버튼은 항상 활성).

### Orval 재생성

## 범위 밖

- 과거 달 탐색(사후 신청 확장)은 이번 요청 범위가 아니라 다루지 않음 — 필요하면 `MAX_MONTH_OFFSET`과 대칭으로 `MIN_MONTH_OFFSET` 개념을 추가하면 된다.
- 근무표는 있지만 아직 결재 마감 전(DRAFT)인 달과 마감(CLOSED)된 달을 구분해 보여주는 것은 하지 않음 — "생성되어 있으면" 신청 가능이라는 기존 규칙을 그대로 따름.
