# 코드리뷰 반영 — 당월 계산 KST, 월 경계 제출 경합, .claude 로컬 설정 제외

앞선 두 작업(`2026-08-05-근무표-미생성월-연차신청-차단.md`, `2026-08-05-연차신청-월-선택-추가.md`)에 대한 코드리뷰에서 지적된 P2 3건을 반영했다.

## [P2] 서버 "당월" 계산이 UTC 기준이라 KST 자정~오전 9시 경계에서 틀림

`leave.service.ts`의 `getRosterStatus()` 기본값이 `new Date().toISOString().slice(0, 7)`(UTC)이라, 한국 시간 자정~오전 9시 사이(예: UTC 7/31 15:30 = KST 8/1 00:30)에는 실제로는 8월인데 7월을 당월로 반환하는 문제가 있었다.

- `leave.service.ts`: `currentYearMonthKst(now = new Date())` 함수 추가 — `Intl.DateTimeFormat('en-US', { timeZone: 'Asia/Seoul', ... }).formatToParts()`로 외부 타임존 라이브러리 없이 KST 기준 `YYYY-MM`을 계산한다. `getRosterStatus()`의 기본 파라미터를 이 함수로 교체.
- 테스트(`leave.service.spec.ts`): `currentYearMonthKst`를 export해 "yearMonth 생략 시 당월 조회" 테스트가 실제 구현과 동일한 함수로 기대값을 계산하도록(이전엔 UTC로 계산해 리뷰가 지적한 버그를 테스트가 오히려 통과시키고 있었음) 수정. `UTC 7/31 15:30 = KST 8/1`, `UTC 7/31 14:59 = KST 7/31` 경계 케이스를 고정 시각으로 검증하는 테스트 추가.

다른 모듈(attendance/roster/approvals)의 `startOfUtcDay` 패턴은 이번 리뷰 지적 범위 밖이라 손대지 않았다 — 서버 프로세스가 UTC로 동작한다는 전제 자체를 시스템 전반에서 KST로 바꾸는 건 별도 작업.

## [P2] 월 경계에서 화면 표시 월과 제출 월이 어긋날 수 있음

기존엔 날짜 선택 화면 렌더 시(`leave-request-page.tsx`)와 제출 시(`use-leave-request.ts`의 `submit()`)가 각각 독립적으로 `new Date()`를 호출해 "이번 달"을 계산했다. 월말에 날짜를 선택해두고 자정을 넘긴 뒤 제출하면, 렌더 시점과 제출 시점의 "이번 달"이 달라져 선택했던 날짜가 다음 달 날짜로 전송될 수 있었다.

- `domain.ts`: `viewedMonth(offset, now)`(호출마다 `new Date()`를 다시 읽음)를 제거하고, `currentYearMonth(now)`(최초 1회 기준 연/월 캡처)와 `addMonthOffset(baseYear, baseMonth, offset)`(순수 계산, 시계를 다시 읽지 않음)로 분리.
- `use-leave-request.ts`: `State`에 `baseYear`/`baseMonth`를 추가해 위저드 시작(`resetWizard` — 홈으로/신청 시작 시에만) 시점에 한 번 고정한다. `monthOffset`으로 이동해도 `baseYear`/`baseMonth`는 그대로이고, 화면 표시(`leave-request-page.tsx`)와 제출(`submit()`) 모두 `addMonthOffset(state.baseYear, state.baseMonth, state.monthOffset)`라는 동일한 파생값을 쓰므로 각자 다른 시점에 시계를 읽어 어긋나는 경우가 구조적으로 없어졌다.
- `initialState`를 상수 객체에서 `initialState()` 함수(React `useState` lazy initializer)로 바꿔, 모듈 로드 시점이 아니라 훅이 처음 마운트되는 시점의 실제 연/월을 기준값으로 잡도록 함께 정리.

## [P2] `.claude/settings.local.json`이 untracked 상태로 남아 있어 실수로 커밋될 위험

로컬에서는 사용자 전역 gitignore(`~/.config/git/ignore`)가 이 파일을 이미 숨기고 있었지만, 저장소 자체의 `.gitignore`에는 규칙이 없어 다른 기여자 환경에서는 `Stop-Process *` 같은 광범위한 로컬 실행 권한이 포함된 파일이 그대로 커밋될 수 있었다.

- `.gitignore`에 `.claude/settings.local.json` 추가.
