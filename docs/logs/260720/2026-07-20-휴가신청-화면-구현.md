# 2026-07-20 apps/mobile 휴가 신청 화면 구현

브랜치: `feat6/mobile-app-scaffold`

## 배경

`docs/mock-ui/휴가신청/휴가신청 (vanilla).html`(순수 HTML/CSS/JS 목업, 기획서 v3.1 US-01~03 기준)을 기준으로 `apps/mobile`에 실제 휴가 신청 화면을 구현했다. 목업은 6개 스크린(홈/1~3단계/완료/현황)을 vanilla JS 상태머신으로 전환하는 방식이었고, 이를 React + TypeScript + shadcn(base-nova)으로 재구현했다.

## 구성

`src/features/leave-request/`

- `types.ts`: `LeaveRequestType`을 apps/web의 `ApprovalRequestType`과 동일한 이름(`SUBSTITUTE_HOLIDAY`)으로 맞춤 — 목업은 `SUBSTITUTE` 약어를 썼지만, 향후 백엔드 연동 시 동일 enum을 재사용할 수 있도록 실제 도메인 표기를 따랐다.
- `domain.ts`: 순수 함수로 분리한 비즈니스 규칙(연차/반차 차감량 D-1, 중복 신청 차단 US-01, 유형별 비활성 사유 C-2, 사후 신청 판정 D-3, 마감 임박 경고 D-4) — 목업의 vanilla JS 로직을 그대로 이식.
- `use-leave-request.ts`: 화면 전환 + 선택 상태 + 신청 목록을 관리하는 훅. 신청은 `crypto.randomUUID()`로 id를 부여해 취소 시 인덱스가 아닌 id로 식별(목업은 배열 인덱스를 썼는데, 목록이 unshift/splice로 바뀌는 구조라 인덱스 기반 키는 위험하다고 판단해 교정).
- `mock-data.ts`: 실제 `new Date()` 기준으로 목업 데이터를 생성한다. 목업은 "2026년 7월, 오늘=10일" 데모용 하드코딩값을 썼지만, 오늘 날짜가 실제로 2026-07이므로 하드코딩 없이 실제 날짜 기준으로 계산하도록 단순화했다.
- `components/`: calendar(달력 그리드), status-pill, request-card, 6개 화면 컴포넌트. 아이콘은 목업의 이모지(☀️🌤️🌇🎁) 대신 컴포넌트.json에 설정된 lucide 아이콘(Sun/Sunrise/Sunset/Gift)으로 대체 — 웹뷰 환경에서 이모지 렌더링 일관성 문제를 피하고 프로젝트 아이콘 라이브러리 컨벤션을 따름.
- `leave-request-page.tsx`: 화면 전환은 라우트가 아닌 컴포넌트 상태(useState)로 처리 — 목업의 단일 페이지 위저드 UX를 그대로 유지(라우트 분리 시 선택 상태 직렬화 등 불필요한 복잡도 추가로 판단).

## 디자인 토큰

`apps/mobile/src/index.css`의 `:root`를 목업 팔레트(크림 배경, 돌봄그린 primary)에 맞게 조정했다. 임의 색상값 대신 **이미 존재하던 도메인 토큰을 재사용**:

- `--background`/`--muted`: 기존 `--paper`/`--paper-strong` 값(크림)을 그대로 사용
- `--primary`/`--primary-foreground`/`--ring`: 기존 `--approve` 값(돌봄그린, oklch(0.52 0.13 150))을 재사용 — 변환해보니 목업의 `#2F7A6B`와 거의 일치해 별도 토큰을 새로 만들 필요가 없었음
- 대기/승인/반려 배지는 apps/web의 `bg-*/10 text-*` 패턴(`badges.tsx`)을 그대로 재사용 — warning/approve/reject 토큰이 이미 목업의 amber/green/red와 맞아떨어짐

새로 추가한 shadcn 컴포넌트: `button`, `card`, `badge`, `alert`, `separator` (CLI로 설치, 수기 구현 없음).

## 검증

- `pnpm --filter mobile build`(tsc + vite), `lint`(oxlint) — 신규 코드 경고 없음(기존 shadcn 생성 파일의 `only-export-components` 경고만 존재, apps/web과 동일 패턴)
- `any` 미사용 확인
- Playwright로 전체 플로우 수동 검증: 홈 → 1단계(달력 — 차단일/사후신청 가능일/7일 초과 비활성 표시) → 2단계(유형별 비활성 사유) → 3단계(잔여 미리보기, 마감 임박·사후 신청 경고) → 신청 완료(애니메이션) → 현황(취소 → 잔여 복원 확인)까지 정상 동작
- 검증 중 오래된 dev 서버 프로세스가 포트를 점유해 혼선이 있었음(스크린샷이 이전 코드 상태를 보여줌) — 프로세스 정리 후 재확인해 해결. 최종 스크린샷은 검증 후 삭제(저장소에 커밋하지 않음)

## 미해결

- 백엔드 연동 전까지는 `mock-data.ts` 기반 로컬 상태로 동작한다. Orval 연동은 CLAUDE.md 원칙대로 실제 API 클라이언트가 필요해지는 시점에 구성.
- 사유 입력 UI는 목업·기획서 원칙(시니어 UX상 강제하지 않음)에 따라 이번 구현에도 포함하지 않았다.
