# 근무표 앞부분에 전월 마지막 7일 미리보기 표기

## 배경

근무표(월 단위 그리드)에서 이번 달 1일부터만 보이면 월 경계에서 근무 흐름(연속 야간 근무 등)을 파악하기 어렵다는 요청으로, 표 맨 앞에 전월 마지막 7일을 읽기 전용으로 함께 표기하도록 했다.

## 구조 확인

- 프론트(`schedule-grid.tsx`)는 `days` 배열을 순회하며 `<th>`/`<td>` 컬럼을 생성하는 구조라 컬럼 추가 자체는 쉬움.
- 백엔드는 "월(yearMonth) = Roster 1건" 구조로 강하게 결합돼 있어(`RosterQueryDto`가 `yearMonth`만 받음, 셀도 해당 월 `rosterId`에만 종속) 전월 데이터를 한 응답에 같이 내려주는 API 확장은 백엔드 변경이 필요함.
- 이번 작업은 백엔드 변경 없이, 프론트에서 이번 달 + 전월 두 번 조회 후 병합하는 방식으로 구현(리스크가 작고 기존 API를 그대로 재사용).

## 구현(apps/web)

### `roster-page.tsx`

- `useGetRoster({ yearMonth })`와 별도로 `useGetRoster({ yearMonth: shiftMonth(yearMonth, -1) })`를 호출해 전월 근무표를 함께 조회(`retry: false`, 전월 근무표가 없어(404) 실패해도 이번 달 화면에 영향 없도록 독립 쿼리로 분리).
- 조회 결과(`prevRoster`)를 `ScheduleGrid`에 prop으로 전달.

### `schedule-grid.tsx`

- `DayMeta`에 `readOnly: boolean` 필드 추가.
- `leadDays`: 이번 달 1일 기준으로 날짜 연산만으로 전월 마지막 7일(`LEAD_DAYS = 7`)을 항상 계산(전월 근무표 조회 성공 여부와 무관하게 컬럼 자체는 항상 표시, 데이터가 있으면 채우고 없으면 빈 칸).
- `days = [...leadDays, ...currentDays]`로 합쳐 기존 테이블 렌더링 구조를 그대로 재사용.
- `cellMap`/`summaryMap`을 `prevRoster.cells`/`prevRoster.summary` + `roster.cells`/`roster.summary` 병합으로 변경(우선순위: 이번 달 데이터가 있으면 그걸 사용).
- 전월 컬럼은 `readOnly: true`로 표시해 `onMouseDown`/`onMouseEnter`(셀 편집·드래그 선택)를 아예 연결하지 않음 — `canEdit && !d.readOnly`로 게이팅.
- 드래그 선택 시 셀 목록(`selectedKeys`, `handleWindowMouseUp`)도 `!d.readOnly` 조건을 추가해 드래그 범위가 전월 컬럼으로 확장되지 않도록 방어.
- 시각적으로 `bg-muted/40` 음영 + 이번 달 시작 직전 컬럼에 굵은 구분선(`border-r-2`)을 추가해 전월/이번 달을 구분. 전월 셀 칩은 `opacity-60`으로 흐리게 표시.
- 헤더/바디/요약행의 React key를 기존 `d.day`(월 경계를 넘으면 날짜가 겹칠 수 있음, 예: 7/28과 8/28)에서 `d.workDate`(YYYY-MM-DD, 항상 유일)로 변경.

### 영향 없음 확인

- `ApplyPresetDialog`에 넘기는 `daysInMonth`는 여전히 `roster.daysInMonth`(이번 달 기준)로 프리셋 적용 로직은 전월 컬럼과 무관.
- 백엔드(apps/api), Orval 생성물, DB 스키마 변경 없음.

## 확인

- `pnpm --filter web exec tsc --noEmit`, `pnpm --filter web lint`(oxlint) 통과.
- 로컬 dev 서버(API+웹)로 `/roster` 화면 실제 렌더링 확인: 8월 근무표 조회 시 7/25(월)~7/31(일)이 음영 처리된 채 앞에 붙어 표기되고, 실제 전월 셀 데이터(근무 코드)가 채워짐. 전월 컬럼 클릭 시 편집 팝오버가 열리지 않는 것도 확인.

## 범위 밖

- 백엔드 API를 확장해 한 응답에 전월 데이터를 포함시키는 방식은 채택하지 않음(리스크가 더 큰 방향이라 프론트 병합 방식을 우선 적용).
- 전월 컬럼 개수(7일)를 사용자가 조정하는 설정은 추가하지 않음(요청 범위 밖).
