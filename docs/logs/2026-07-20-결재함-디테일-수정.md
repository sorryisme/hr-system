## 1. 결재 단계 스테퍼 CSS 간격 수정

**점검 결과: 조정 필요했음.** 기존 `approval-stepper.tsx` 구조의 문제:

- 각 단계 래퍼가 전부 `flex-1`인데 첫 래퍼에는 연결선이 없어, 1차 dot 오른쪽에 빈 공간이 생기고 연결선이 dot에서 뚝 떨어진 지점에서 시작됨.
- 연결선이 라벨 칼럼의 바깥 경계에서 끝나 라벨 폭(직책명 길이)에 따라 dot↔선 간격이 들쭉날쭉함.
- dot 간 간격 불균등(1↔2차 간격이 2↔3차의 약 2배).
- 연결선 `mt-2 h-0.5`가 dot(size-4) 중심보다 1px 아래.

**수정:** 표준 스테퍼 패턴으로 재구성 — 각 단계를 균등 폭 칼럼(`flex-1 flex-col items-center`)으로 만들고, 연결선을 `absolute right-1/2 + w-full`로 이전 dot 중심↔현재 dot 중심을 잇도록 배치(`h-4 flex items-center`로 수직 중앙 정렬). dot이 연결선 위에 그려져 선이 dot 뒤를 통과하는 형태. 진행 상태 색상(`bg-approve`/`bg-border`)·전결 표기 로직은 유지.

## 2. 결재자 = 로그인 사용자 전환

기존에는 인증 미도입 보완으로 body `approverId` + 프론트 "결재자로 실행" 셀렉트로 결재자를 골라 실행했다. 관리자 로그인(JWT)이 도입되었으므로 세션 사용자 기반으로 전환.

**백엔드 (`apps/api`)**
- `POST /requests/:id/approve` — body 제거, `@CurrentUser()`의 `user.id`를 결재자로 사용. `ApproveRequestDto` 삭제.
- `POST /requests/:id/reject` — `RejectRequestDto`에서 `approverId` 제거(comment만 유지), 결재자는 세션 사용자.
- 서비스 로직(자기결재 금지 D-6, NOT_YOUR_STEP, 낙관적 경합 가드)은 변경 없음 — 단위 테스트 32건 통과.
- `openapi.json` 재export → 웹 Orval 클라이언트 재생성.

**프론트 (`apps/web`)**
- 상세 패널의 "결재자로 실행" 셀렉트·`actorOptions` 제거. `getSessionUser()`로 결재자 표시("결재자: 박든든 사무국장").
- 로그인 사용자가 현재 단계의 결재자/대결자가 아니거나 신청자 본인이면 승인·반려 버튼 비활성화 + 안내 문구(불필요한 409 예방, 서버 검증은 그대로 이중 수행).

**시연 흐름 참고:** 픽스처의 1차 결재자(이살핌·사회복지사)는 STAFF라 웹 로그인 대상이 아니지만, 1차 대결자 = 박든든(사무국장)이므로 사무국장 계정으로 1차(대결)~2차, 시설장 계정으로 3차 결재가 가능하다. 종사자 인증(Phase 3) 도입 시 본결재자 경로로 자연 전환.

**검증:** 웹 빌드(tsc+vite)·API jest 통과. dev 서버 기동 후 사무국장 계정 로그인 → 결재함 상세에서 스테퍼 렌더링·결재자 표시·버튼 활성화 화면 확인(승인 클릭까지의 E2E는 시드 데이터 보존을 위해 생략 — 서버 로직은 기존 테스트 커버리지 범위).

## 3. dev_plan_0717.md §4.10(결재·Phase 1 연동 및 설정 A-6) 누락 점검

현재 구현 범위: auth(관리자 로그인)·approvals(결재함 A-3)·dashboard 화면. DB 스키마(v1.2)에는 Roster/ScheduleEntry/ShiftType/RegulationParamSet/DailyStaffingRule/MonthlyCensus/SubstituteHolidayLedger/Notification 등 §4.10 관련 모델이 모두 존재하나, **API 모듈·화면은 전부 미구현**이다.

| §4.10 항목 | 상태 | 비고 |
| --- | --- | --- |
| `request.step_approved`/`request.approved` 이벤트 발행·구독 → 근무표 가반영/확정 반영 | 미구현 | approvals.service에 이벤트 발행 코드 없음. 근무표(A-2) 모듈 자체가 미구현이라 선행 의존 |
| 결재함 상세 패널에 해당일 근무표 요약 병행 표시 | 미구현 | **결재함 범위의 유일한 직접 누락.** ScheduleEntry 데이터·근무표 API 필요 — A-2 슬라이스와 함께 구현 권장 |
| 종사자 내 근무표(B-3, 스와이프+◀▶, 월 근무표) | 미구현 | 종사자 모바일 화면 전체 미착수(Phase 3 인증 의존) |
| 유대 관리대장(A-4) 사용예정일자 자동 연동 | 미구현 | SubstituteHolidayLedger 모델만 존재. 결재 승인 이벤트 연동 필요 |
| 설정(A-6): 시설 정보·고시 파라미터·일별 적정 인원·가산 목표·근무유형 정의 | 미구현 | Facility/RegulationParamSet/DailyStaffingRule/ShiftType 모델 존재, 설정 API·화면 없음 |

결론: §4.10은 근무표(Phase 2) 착수를 전제로 하는 항목들이라 현 시점 "누락"이라기보다 미착수이며, 결재함 자체에 직접 걸리는 항목은 **상세 패널의 해당일 근무표 요약 표시** 1건이다. A-2(근무표 편집기) 슬라이스 시 결재 이벤트 발행(가반영/확정 반영)과 함께 구현해야 한다.
