# Prisma v6 → v7 업그레이드 (2026-07-09)

## 배경

`docs/logs/2026-07-09-nestjs-prisma-orm-세팅.md`에서 Prisma v7의 아키텍처 변경(드라이버 어댑터 필수, `datasource.url` 분리, generator 변경)이 AGENTS.md의 "Prisma Next 메이저 업그레이드는 사람 승인 없이 수행하지 않는다" 규칙 대상이라 보류하고 v6.19.3으로 고정해두었다. 사용자가 v7로의 업그레이드를 명시적으로 요청해 진행했다 — 이 요청 자체를 해당 규칙의 사람 승인으로 간주한다.

## 변경 사항

- `@prisma/client`, `prisma`: `^6.19.3` → `^7.8.0`
- 신규 의존성: `@prisma/adapter-mariadb`(런타임 드라이버 어댑터, MySQL과 호환되는 MariaDB 드라이버 사용), `dotenv`(CLI 전용, `prisma.config.ts`에서 `.env` 로드)
- `apps/api/prisma/schema.prisma`: `datasource db`에서 `url = env("DATABASE_URL")` 제거. generator는 `prisma-client-js`를 유지(v7에서도 지원 확인됨 — `prisma-client`로의 전환은 하지 않음).
- `apps/api/prisma.config.ts` 신규: CLI(migrate/studio/db seed)가 사용할 `DATABASE_URL`과 마이그레이션 경로, 시드 명령(`ts-node prisma/seed.ts`)을 정의. `package.json`의 `prisma.seed` 필드는 여기로 이전하고 제거했다.
- `apps/api/src/prisma/prisma.service.ts`: 런타임 `PrismaClient`를 `@prisma/adapter-mariadb`의 `PrismaMariaDb` 어댑터로 생성하도록 변경. `DATABASE_URL`이 없으면 즉시 에러.

## 사람 검토 필요 — DB 커넥션 처리 변경

CLAUDE.md/AGENTS.md의 DB/Infra 규칙: "DB 커넥션 처리 변경(풀, 타임아웃, 재시도)은 사람 검토 필수 (Multi-AZ failover 대응)."

드라이버 어댑터 도입은 이 규칙에 해당한다 — 기존에는 Prisma의 내장 쿼리 엔진(Rust)이 커넥션 풀/타임아웃/재시도를 관리했지만, 이제는 `mariadb` npm 드라이버(및 그 `Pool` 옵션)가 이를 담당한다. 현재는 `new PrismaMariaDb(databaseUrl)`에 문자열 URL만 넘겨 드라이버 기본값을 그대로 쓰고 있다. **운영 배포 전에 사람이 아래를 검토해야 한다:**
- `mariadb` 드라이버의 기본 풀 크기·연결 타임아웃·재연결/재시도 정책이 Multi-AZ MySQL(RDS 등) failover 시나리오에 적합한지.
- 필요 시 `PrismaMariaDb` 생성자에 `mariadb.PoolConfig`(connectionLimit, acquireTimeout, trace 등)를 명시적으로 전달할지 여부.

## 검증

- `pnpm --filter api build` / `lint` / `test` 통과.
- `npx prisma format` / `npx prisma validate` 통과 (`prisma.config.ts` 로드 확인).
- `npx prisma generate` 로 v7 클라이언트 생성 확인.
- 실 DB가 없어 `migrate deploy`/실제 커넥션 테스트는 수행하지 못했다 — DB 준비 후 확인 필요.

## 후속 작업

1. 위 "DB 커넥션 처리 변경" 사람 검토 완료.
2. `DATABASE_URL`을 사내 시크릿 관리 솔루션에서 주입하도록 배포 파이프라인 구성(기존 후속 작업, 변경 없음).
