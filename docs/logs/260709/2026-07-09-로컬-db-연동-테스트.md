# 로컬 MySQL 연동 테스트 (2026-07-09)

## 배경

사용자가 로컬에 MySQL을 `127.0.0.1:3306`에 띄워주어, Prisma v7 세팅이 실제 DB에 붙는지 확인했다.

## 진행

1. `carehome_tms` 데이터베이스가 없어 새로 생성(`utf8mb4`/`utf8mb4_0900_ai_ci`).
2. `npx prisma migrate deploy` 실행 시 `P3005`(스키마가 비어있지 않음) 오류 — 확인해보니 DB에 21개 테이블이 이미 모두 존재했고, `leave_balance.remaining` 생성 컬럼·`approval_history`의 append-only 트리거까지 우리 baseline 마이그레이션과 정확히 일치했다(누군가 이미 `docs/ddl/carehome_tms_ddl_v1.1.sql`을 직접 적용해둔 것으로 보임). 재실행 대신 `npx prisma migrate resolve --applied 20260709000000_init`으로 "이미 적용됨" 처리했다.
3. 샘플 시설(`샘플요양원`)·근무유형 7종도 이미 존재해 별도 시딩은 하지 않았다.
4. `@prisma/adapter-mariadb` 기반 `PrismaClient`로 직접 쿼리해 연결·조회 확인.
5. `pnpm --filter api build` 후 `dist/src/main.js`를 실행해 Nest 앱이 실제로 기동되고 `GET /`, `GET /api/docs/json`이 200을 반환하는지 확인.

## 코드 변경: main.ts에 dotenv 자동 로드 추가

앱을 그냥 기동하면 `PrismaService`가 `DATABASE_URL is not set`으로 즉시 실패했다 — `prisma.config.ts`는 CLI(migrate 등)에서만 `.env`를 읽고, 실행 중인 Nest 앱 자체는 `.env`를 읽지 않았기 때문이다.

`apps/api/src/main.ts` 최상단에 `import 'dotenv/config'`를 추가했다. `.env` 파일이 있으면 로컬 개발용으로 값을 채워주고, 이미 설정된 환경변수는 덮어쓰지 않으므로 운영 환경(시크릿 관리 솔루션이 실제 값을 주입)에서는 아무 영향이 없는 no-op이다. 이에 맞춰 `dotenv`를 `devDependencies`에서 `dependencies`로 옮겼다(런타임 코드 경로에서 import하므로).

## 보안 참고

사용자가 대화창에 DB 비밀번호를 평문으로 공유했다. 이 값은 `apps/api/.env`(gitignore 대상)에만 저장했고 어떤 응답·커밋·문서에도 그대로 출력하지 않았다. 로컬 테스트 전용 값이 아니라면(다른 곳에서도 재사용 중이라면) 교체를 권장한다.

## 검증

- `pnpm --filter api build` / `lint` / `test` 통과.
- `npx prisma migrate status` → "Database schema is up to date!"
- Prisma 클라이언트로 `facility`/`shiftType` 조회 성공.
- `node dist/src/main.js` 로 앱 기동, `GET /` 및 `GET /api/docs/json` 200 확인 (테스트 후 프로세스 종료).
