# 휴가 신청 페이지 구현 (2026-07-10)

## 배경

`feat/web-leave-request-page` 브랜치에서 `docs/mock-ui/휴가신청 (vanilla).html` 목업(순수 HTML/CSS/JS)을 기준으로 apps/web에 실제 React 페이지를 구현했다. apps/api에 휴가 신청 관련 API가 아직 없어 임시 목데이터로 화면 흐름만 우선 구현했다.

## 구현 내용

- 라우트: `apps/web/src/routes/leave-request.tsx` (`/leave-request`)
- 기능 모듈: `apps/web/src/features/leave-request/`
  - `types.ts` — `LeaveType`/`RequestStatus`/`LeaveRequestItem`/`WizardScreen`
  - `constants.ts` — 휴가 유형 메타(`TYPE_META`), 상태 라벨(`STATUS_TEXT`)
  - `utils.ts` — 목업의 vanilla JS 비즈니스 로직을 순수 함수로 포팅
    (`deductAmount`, `blockedDaySet`, `typeDisabledReason`, `hasPastSelected`, `hasDeadlineWarning`, `rangeText`, `typeLabel`)
  - `mock-data.ts` — **임시 목데이터** (사용자 정보, 초기 잔여일수, 신청 내역 3건). API 연동 시 제거 대상으로 주석 표기함
  - `components/` — `HomeScreen`, `DateSelectScreen`(달력), `TypeSelectScreen`, `ConfirmScreen`, `DoneScreen`, `StatusScreen`, `RequestCard`, `StatusPill`
  - `LeaveRequestPage.tsx` — 화면 전환(home/step1/step2/step3/done/status) 및 상태(선택 날짜/유형/잔여일수/신청목록) 관리
- 목업의 폰 프레임(데코레이션)은 걷어내고 실제 반응형 웹페이지(`max-w-md` 중앙 정렬)로 구현
- 날짜는 목업처럼 하드코딩된 "2026년 7월" 데모값 대신 실제 `new Date()` 기준으로 동작하도록 일반화

## 디자인 토큰

CLAUDE.md의 "디자인 토큰 외 임의 색상값(arbitrary value) 금지" 규칙에 따라, 목업의 브랜드 컬러(돌봄그린/앰버/크림)를 `apps/web/src/index.css`의 `@theme`/`:root`/`.dark`에 새 시맨틱 토큰으로 추가했다(기존 `--destructive` 패턴과 동일한 방식):
  - `--success` / `--success-foreground` (돌봄그린 — 승인/연차 관련 강조)
  - `--warning` / `--warning-foreground` (앰버 — 대기중/경고)
  - `--care-cream` (페이지 배경. 다크모드에서는 `--background`로 폴백)
- 반려/오류 표시는 기존 `--destructive` 토큰을 재사용(신규 red 토큰 추가하지 않음)
- 전역 `--primary`(shadcn 기본 뉴트럴)는 변경하지 않음 — 앱 전체 브랜드 컬러 결정은 이번 스코프 밖이라 판단, 이 화면에서만 `success` 토큰을 명시적으로 사용

## 검증

- `pnpm exec vite build` — 라우트 트리(`routeTree.gen.ts`) 정상 재생성 확인(직접 수정 안 함)
- `pnpm exec tsc -b` — 타입 에러 없음
- `pnpm lint` — 신규 파일 관련 경고 없음(기존 파일의 fast-refresh 경고 3건은 이번 작업과 무관)
- `vite preview` + headless Chrome 스크린샷으로 홈 화면 렌더링 확인(잔여 연차/휴일대체 카드, 신청 현황 카드, 토큰 컬러 정상 반영)
- 나머지 5개 화면(달력/종류선택/확인/완료/현황)은 클릭 인터랙션 스크린샷까지는 수행하지 못했음 — 로직은 목업의 검증된 vanilla JS를 그대로 포팅했고 빌드/타입체크는 통과했으나, 실제 클릭 흐름 시각 확인은 후속으로 필요
