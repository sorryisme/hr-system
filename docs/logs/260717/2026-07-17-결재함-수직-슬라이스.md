# 결재함(결재 승인) 수직 슬라이스 — NestJS + React (2026-07-17)

## 배경

기획서 v3.2(`docs/plan/dev_plan_0717.md` §3)와 결재 승인 목업(`docs/mock-ui/결재승인/결재 승인.html`,
1안 — 목록 + 우측 상세 패널 분할형)을 기준으로 관리자 웹 결재함(A-3)을 end-to-end로 구현했다.
Prisma v1.2 스키마는 기존 반영분을 그대로 사용했다(스키마 변경 없음).

## 확정 범위 (사용자 선택)

- UI = 목업 1안(분할 패널). 2안(모달형)은 미채택
- 백엔드 = 결재함 수직 슬라이스만: 목록/상세/승인/반려 + §3.4 상태머신(전결 포함).
  **신청 생성(POST /api/requests)은 미구현** — 시드 데이터로 대체
- **인증 완전 생략**: 결재자 식별을 body의 `approverId`로 받는다. JWT/RBAC는 Phase 0 별도 작업
  (컨트롤러에 TODO 주석으로 가드 적용 지점 명시)
- 프론트 연동 = Orval + React Query (fetch 커스텀 mutator, axios 미사용)

## 신규 의존성 (CLAUDE.md 규칙에 따른 사유 기록 — 계획 승인으로 갈음)

| 패키지 | 위치 | 사유 |
|---|---|---|
| class-validator, class-transformer | apps/api deps | DTO 검증(400 REASON_REQUIRED 등). Nest ValidationPipe 표준 페어 |
| @tanstack/react-query | apps/web deps | Orval react-query 클라이언트 타깃 |
| orval | apps/web devDeps | OpenAPI → 타입+훅 생성 (API 타입은 Orval 생성물만 사용 규칙) |

## 구현 내용

### apps/api

- `src/main.ts`: 전역 프리픽스 `api`(§3.7 경로 정합), 전역 ValidationPipe(whitelist+transform),
  CORS(localhost:5173 — 로컬 dev 전용), Swagger operationIdFactory(메서드명 → Orval 훅 이름)
- `src/openapi.ts`: main.ts(서빙)와 export 스크립트가 공유하는 OpenAPI 문서 생성기
- `src/approvals/`(신규 모듈):
  - `GET /api/requests?status=` — `InboxStatusFilter(PENDING|APPROVED|REJECTED)`,
    대기 탭은 PENDING+INTERIM_APPROVED 묶음. 응답 envelope `{ items, counts }` —
    groupBy 1회로 탭 배지 수 제공. **페이지네이션 생략(시드 ~10건 규모, 후속 필요)**
  - `GET /api/requests/:id` — requester/desiredShift/targetDates/requestLines(스냅샷)/histories 포함
  - `POST /api/requests/:id/approve`, `POST /api/requests/:id/reject`(사유 필수)
  - 상태머신(§3.4): 전결(D-13, step2 delegationEnabled → 즉시 APPROVED + isFinalByDelegation),
    자기결재 금지(D-6), 대결자 허용, 낙관적 가드(`updateMany` status/currentStep 조건 — 엣지 1),
    최종 승인 시 잔여 정산(used↑/reserved↓ — SUBSTITUTE_HOLIDAY는 substituteHolidayBalance),
    반려 시 reserved만 해제. **remaining은 DB GENERATED — 앱에서 쓰지 않음**
  - 서명 스냅샷(D-12): history에 경로 문자열만 기재. 실제 스토리지 복사는 TODO
  - 에러: 400 `REASON_REQUIRED`/`INVALID_ID`, 409 `ALREADY_FINALIZED`/`NOT_YOUR_STEP`/`SELF_APPROVAL_FORBIDDEN`
  - BigInt id·Decimal은 DTO에서 string으로 명시 매핑, enum은 전부 `enumName` 지정(Orval 공유 enum)
  - `approvals.service.spec.ts` — 상태머신 13케이스(전이 5종·전결·대결자·409 3종·반려 3종)
- `scripts/export-openapi.ts` + `openapi:export` 스크립트: **DB 연결 없이** OpenAPI 문서를
  `apps/api/openapi.json`으로 내보낸다(NestFactory.create는 onModuleInit 미호출, 어댑터는 생성
  시점에 커넥션을 열지 않음). 계획서의 "웹에서 라이브 서버 fetch" 방식 대신 채택 — 서버·DB 없이
  재현 가능해 계획의 취지(재현 가능한 생성 입력)에 더 부합
- `prisma/seed.ts` 확장: 팀 2, 직원 8(결재 권한자 3인 서명 더미 — 전원 가상 인명), 결재선 3단계,
  잔여(reserved=열린 신청 합계와 정합), 신청 10건(PENDING 4·INTERIM 2·APPROVED 2(전결 1)·REJECTED 2)
  + 제출 시점 결재선 스냅샷 + append-only 이력.
  **재실행 전략**: approval_history의 UPDATE/DELETE 차단 트리거 때문에 delete-and-recreate 불가 →
  `approvalRequest.count() > 0`이면 신청 블록 스킵(count-guard). 완전 재시드는 로컬 `migrate reset`만

### apps/web

- Orval 파이프라인: `orval.config.ts`(input `../api/openapi.json`, react-query + fetch,
  clean), 생성물 `src/api/generated/`(수정 금지), `src/api/mutator.ts`(수작성 — VITE_API_URL
  프리픽스, 4xx body의 `code`를 담은 ApiError). `generate:api` 스크립트, `.env.example` 추가
- `main.tsx`에 QueryClientProvider 추가
- 디자인 토큰(`src/index.css`, 기존 중립 테마에 추가만): `brand`(네이비)·`approve`(그린)·
  `reject`(레드 — 전역 destructive와 분리)·`paper`/`paper-strong`(크림). 라이트/다크 모두 정의.
  **컴포넌트에 임의 색상값 0건**
- shadcn CLI로 badge/textarea/tabs/card/select 추가
- `routes/approvals.tsx` + `features/approvals/`:
  approval-inbox-page(톱바·탭 배지·분할 레이아웃), request-list, request-detail-panel,
  approval-stepper(전결 생략 표시 포함), signature-boxes, reject-form(사유 필수), badges, labels
- **결재자 선택 셀렉트**(인증 생략 보완): 스냅샷 결재선의 결재자·대결자 후보 중 선택해
  `approverId`로 전송 — NOT_YOUR_STEP/자기결재 409도 시연 가능
- 뮤테이션은 invalidation-only. 409/400 시 에러 배너 표시 + 서버 상태로 재동기화
