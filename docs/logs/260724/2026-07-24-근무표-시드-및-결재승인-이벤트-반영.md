## 1. 근무표 데모 시드 (`prisma/seed.ts`)

`GET /rosters` 응답 확인 및 DDL v1.3 신설 필드 시연을 위해 2026년 7월 데모 근무표를 추가했다.
`seedRosterFixtures(facilityId)`를 `main()`에서 호출(결재 픽스처 이후 — 팀/직원 의존).

- **월 근무표:** facility 1, `2026-07`, `DRAFT` (upsert)
- **일별 적정 인원(§4.5):** 시설 전체 `DAY min=2`, `NIGHT min=1` (teamId=null은 Prisma 복합 unique upsert 불가 → `findFirst` 가드)
- **셀 186건:** 교대 직원 6명(id 4~9) × 31일. dow 기반 주간 패턴, `'N'`은 직원별 야간유형(N/NF)으로 확정. `upsert(uq_entry)`
- **v1.3 기능 시연 오버라이드:**
  - `4-13` → 주간 + `override 07:30~17:00` (셀 시간 조정, F-01)
  - `7-20` → 유대(SUB) + `source_ledger_id`(carryable 150분 = 유(2,30), F-02) — 대장 1건 함께 생성
  - `5-10`·`6-8` → 승인된 연차(#7·#8) 확정 반영 예시(`source=APPROVAL`)
  - `8-16` → 병가(D-18, 관리자 직접 입력)
- **재시드 가드:** `scheduleEntry.count() > 0`이면 스킵(완전 재시드는 로컬 `migrate reset`)

## 2. 결재 승인 → 근무표 반영 (이벤트 구독)

계획 §2.3/§4.10의 이벤트 발행 방식을 구현했다. **신규 의존성 없이** Node 내장 `EventEmitter`를
NestJS 프로바이더로 감쌌다(`@nestjs/event-emitter` 등 미도입 — CLAUDE.md 의존성 정책 준수).

**신설**
- `src/events/domain-events.ts` — 이벤트 이름(`request.approved` / `request.step_approved`) + `ApprovalReflectionPayload`
- `src/events/domain-event-bus.ts` — `DomainEventBus`(publish/subscribe, 구독자 예외 격리)
- `src/events/events.module.ts` — `@Global` 제공(발행·구독 모듈 경계 넘어 동일 인스턴스 주입)
- `src/roster/roster-reflection.service.ts` — `RosterReflectionService`(`OnModuleInit`에서 구독)

**발행부** `approvals.service.ts`
- `approveRequest`를 트랜잭션 결과 캡처 → **커밋 이후** 발행하도록 변경(구독자가 확정 상태를 읽도록)
- 최종 승인 → `REQUEST_APPROVED`(확정 반영, `is_provisional=false`)
- 1차 승인(`nextStepNo===1`) → `REQUEST_STEP_APPROVED`(가반영, `is_provisional=true`)
- 중간 2차 승인은 근무표 이벤트 없음(§4.10)

**반영 규칙** (`RosterReflectionService`)
- 유형→근무유형: ANNUAL→AL, HALF_AM→HAM, HALF_PM→HPM, SUBSTITUTE_HOLIDAY→SUB, SHIFT_CHANGE→`desiredShiftId`(+`desired_*`→override 시각)
- 대상일 월의 근무표를 찾아 `schedule_entry` upsert(`source=APPROVAL`, `sourceRequestId`). 근무표 없으면 스킵+경고
- CANCEL은 반영 대상 아님(원건 취소 시 셀 원복은 후속 TODO)
- 반영 실패는 로그만 — 이미 커밋된 결재 결과에 영향 없음
