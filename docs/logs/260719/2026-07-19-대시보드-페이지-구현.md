# 대시보드 페이지 — React 정적 UI (2026-07-19)

## 배경

대시보드 목업(`docs/mock-ui/대시보드/대쉬보드.html`)을 기준으로 `feat2/dashboard-page` 브랜치에서
`/dashboard` 라우트를 구현했다. 목업은 좌측 사이드바 + 상단 헤더 셸 안에 대시보드/직원명단/근무표/
결재함 4개 화면이 전환되는 통합 번들이었고, 이번 작업은 그중 `isDashboard` 블록(카드 6개 + 경고
Alert)과 셸 레이아웃을 대상으로 한다. 백엔드 대시보드 API는 아직 없다.

## 확정 범위 (사용자 선택)

- 목업의 사이드바+헤더 셸을 **앱 공통 레이아웃**(`__root.tsx`)으로 도입 — 이후 라우트가 이 셸을
  공유한다. 단, 기존 결재함 페이지(`approval-inbox-page.tsx`)는 자체 상단 브랜드 바를 그대로
  유지하기로 해, 현재 `/approvals` 진입 시 셸 헤더와 결재함 자체 헤더가 이중으로 보인다
  (아래 "미완료" 참고).
- 카드 데이터는 **정적 목업 데이터**(`features/dashboard/mock-data.ts`)로만 채운다. 실제 API
  연동은 대시보드 엔드포인트가 생기면 별도 작업으로 진행한다.

## 구현 내용

### apps/web

- 디자인 토큰(`src/index.css`, 기존 토큰에 추가만): `warning`(앰버) 라이트/다크 정의 —
  목업의 badge/alert `warning` 상태(고시기준 위반, 연차 소멸 임박 등)에 대응. 기존
  `brand`/`approve`/`reject`/`paper` 패턴과 동일하게 `@theme inline`에도 매핑
- shadcn CLI로 `progress`/`alert`/`avatar` 프리미티브 추가(`components/ui`) — 기존
  `badge`/`button`/`card` 등과 함께 사용
- `components/shared/app-shell.tsx`(신규): 좌측 사이드바 내비(대시보드·결재함은
  TanStack Router `Link`로 연결, 직원명단/근무표는 아직 라우트가 없어 비활성 placeholder로만
  표시) + 상단 헤더(라우트별 타이틀, 시설명·날짜는 목업 값 그대로 하드코딩). `__root.tsx`가
  이 컴포넌트를 렌더링하도록 변경(`Outlet`을 AppShell 내부로 이동)
- `features/dashboard/`(신규):
  - `dashboard-page.tsx` — 카드 6개(① 인력충족 현황 ② 오늘 주/야 근무자 ③ 미결재 신청
    ④ 가산 점수 ⑤ 고시기준 위반 경고 ⑥ 연차 소멸 임박자) + 하단 경고 Alert. 3열 그리드 2행
  - `status-badge.tsx` — success/warning/error 3톤을 `approve`/`warning`/`destructive`
    토큰에 매핑하는 얇은 래퍼(기존 `features/approvals/badges.tsx`와 동일한
    "Badge outline + cva 클래스 합성" 패턴)
  - `mock-data.ts` — 목업 HTML의 표기값을 그대로 상수화(인력충족 배지 문구, 주/야 근무
    9/8·1/2, 가산 점수 82/4.9/6.0, 위반·연차 경고 문구 등)
- `routes/dashboard.tsx`가 `DashboardPage`를 렌더링하도록 교체(라우트 파일 자체는 이전
  작업에서 이미 생성됨)

## 목업 대비 확정 편차

- 목업은 `var(--text-display)`/`var(--font-mono)` 등 이 프로젝트 테마에 없는 토큰을 참조 —
  `--text-display`는 대응 토큰을 새로 만들지 않고 Tailwind 기본 크기 유틸(`text-3xl`)로 대체.
  `font-mono`는 Tailwind 기본 모노스페이스 스택으로 충분해 별도 토큰 추가 없음
- 사이드바 브랜드 텍스트("CareShift")·헤더 우측 시설명·날짜("해피케어 주간보호센터 ·
  2026.07.19")는 목업 표기를 그대로 사용(실제 제품명·시설명 확정 전까지 임시)
