# 요양원 근태관리 프로그램 — 개발 기획서 v3.1

> v3.0(결재 우선 순차 개발 기획)에 **확장 기획안(0709)** 의 확정 내용을 병합한 문서.
> 방침은 v3.0과 동일: ① 고시 기준 수치는 원문 값을 확정 스펙으로 사용 ② **결재 시스템을 1순위로 순차 개발**.

## 1. 프로젝트 개요 및 타겟 정의

- **목적:** 장기요양보험 고시 기준을 준수한 정확한 근태관리 프로그램 제작 → 근무관리 업무 효율성 증진.
- **주요 타겟:** 평균 60세 이상의 요양원 근무자(남·여).

**타겟 페르소나 — 베이비붐 세대의 여성 근로자**

1. 시력·청력 등 신체 기능 노화 → 큰 글씨·고대비·진동 피드백 필수.
2. 평균 학력 초졸 수준 → 쉬운 한글 용어 + 괄호 병기(예: "하루 종일 쉬기(연차)"), 문장형 안내.
3. 변화와 기술에 대한 보수적 태도 → 종이 병행 기간 허용, 3단계 이내 신청, 학습 부담 최소화.
4. 육체노동자 → 짧은 조작 시간, 원터치 중심(출퇴근 태그 등).

이 페르소나는 전 Phase의 UX 판단 기준이며, §7 비기능 요구사항의 근거다.

## 2. 개발 로드맵 (순차 개발 전략)

### 2.1 왜 결재 시스템이 먼저인가 — 기획 관점 정리

| 근거 | 설명 |
|---|---|
| 의존성 최소 | 결재는 직원 마스터 + 인증만 있으면 독립 동작. 반면 근무표 엔진은 고시 계산·프리셋·검증까지 필요해 초기 리스크가 큼 |
| 즉시 체감 가치 | 종이 연차신청서 → 모바일 신청 전환 순간 종사자·관리자 모두 효용 체감. 60세+ 사용자의 앱 수용성 조기 검증 |
| 데이터 축적 | 결재로 확정된 연차/유대/근무조정 데이터가 근무표 모듈의 입력값. 선행 구축 시 Phase 2가 실데이터로 시작 |
| 사용성 리스크 조기 검증 | "3단계 이내 신청" 등 시니어 UX 가설을 가장 단순한 모듈에서 먼저 실험 |

### 2.2 단계 정의

```
Phase 0. 공통 기반          (결재의 전제조건)
  - 인증(기기등록+PIN), 직원 마스터, 역할/권한, 시설 기본정보, 서명 이미지 등록
Phase 1. ★결재 시스템        (본 문서의 상세 기획 대상)
  - 연차/반차/유급휴일대체 신청·승인·반려, 근무조정 신청, 결재함, 알림,
    감사로그, 전자서명 결재, 잔여(연차·유대) 관리
Phase 2. 근무표 작성 엔진     (§4 확정 스펙)
  - 근무표 편집기, 프리셋(주야비 3조 2교대), 월별/일별 인력 검증,
    가산 계산(인력배치추가·야간직원배치·간호사배치), 경고 팝업
  - Phase 1 산출물(승인된 연차·유대)을 근무표에 자동 반영
Phase 3. 출퇴근 (GPS)
  - 원터치 태그(지정 반경, 처리 3초 이내), 수동태그 폴백(→ Phase 1 결재 엔진 재사용),
    실근무시간 산정, 법정공휴일 근무 감지 → 유대 부여 후보 제시
Phase 4. 마감·내보내기
  - 근무표 마감, Excel 내보내기(공단입력용 / 사내 게시용 근무표 / 출퇴근부)
Phase 5. (백로그) 근로기준법 검토 엔진
  - 노동법 위반 검토·예방, 세무사 협업 급여산정자료 export, 연차 자동산정
```

### 2.3 단계 간 인터페이스 계약 (결재를 독립 개발하기 위한 장치)

Phase 1은 후속 모듈이 없어도 완결 동작해야 한다. 이를 위해:

- **이벤트 발행 방식:** 결재 승인 시 `request.approved` 이벤트를 발행만 한다. Phase 1 시점의 구독자는 "알림 모듈"뿐이고, Phase 2에서 "근무표 반영 모듈"이 구독자로 추가된다. → 결재 코드는 이후 단계에서 수정 불필요.
- **잔여(연차·유대) 관리는 Phase 1에 포함:** 근무표 없이도 부여/사용/잔여가 계산되도록 employee 마스터에 귀속.
- **근무조정 신청은 Phase 1에서 "기록·결재"까지만:** 실제 근무표 셀 변경은 Phase 2에서 이벤트 구독으로 구현. Phase 1 기간에는 승인 결과를 관리자가 수기 근무표(기존 방식)에 반영한다고 가정.
- **유대 부여는 Phase 1에서 관리자 수동:** 법정공휴일 근무 사실의 자동 감지는 Phase 3(출퇴근 데이터) 이후. Phase 1에서는 관리자가 공휴일 근무를 확인하고 유대를 수동 부여한다(§3.6 D-10).

### 2.4 Phase 1 성공 지표 (기획 KPI)

- 종사자 신청 완료율(신청 시작 → 제출) ≥ 90%
- 신청 1건 소요 시간 ≤ 60초 (시니어 사용자 실측)
- 종이 신청서 병행 비율: 도입 2개월 내 20% 이하
- 결재 처리 리드타임(신청→승인/반려) 중앙값 ≤ 24시간

## 3. Phase 1 상세 기획 — 결재 시스템

### 3.1 범위 정의

**포함**
- 신청 유형: 연차(종일), 오전반차, 오후반차, **유급휴일대체(유대)**, 근무조정(대상일+희망 근무형태)
- 결재선: 1단계(관리자) 또는 2단계(관리자→시설장/상급관리자), 시설 설정으로 선택
- 결재함(관리자 웹), 신청·현황(종사자 모바일)
- 잔여 관리: 연차(부여/사용/잔여, 승인 시 자동 차감) + 유대(부여/사용/잔여, 당해 연도 소멸)
- **전자서명:** 승인 시 결재자의 저장된 서명 이미지가 결재란에 기재(출력용 서식 포함)
- 알림(인앱 필수, 푸시/알림톡은 정책 결정 D-7), 감사로그, 신청서 PDF/출력용 뷰

**제외 (후속 단계)**
- 근무표 자동 반영(Phase 2), 수동 출퇴근 태그 결재(Phase 3 — 단, 결재 엔진은 유형 추가만으로 재사용 가능하게 설계)
- 유대 자동 부여(Phase 3에서 출퇴근 데이터 기반 후보 제시), 유대의 공단 인정시간 산정(Phase 2/4 — §4.4)
- 병가·경조휴가 등 기타 휴가 유형(유형 확장 가능한 구조만 확보)

### 3.2 사용자 스토리 및 인수 조건

**US-01. 종사자 연차/유대 신청**
> 요양보호사로서, 다음 주 연차를 휴대폰에서 신청하고 싶다. 종이 신청서를 쓰고 사무실까지 가지 않기 위해서다.

인수 조건:
- Given 로그인한 종사자가 / When 날짜 1개 이상 선택 → 종류 선택 → "신청하기" 3단계를 완료하면 / Then 신청이 `대기` 상태로 생성되고 결재자에게 알림이 간다.
- 사유 입력은 선택 사항이다(입력 강제 금지 — 시니어 UX 원칙).
- 선택한 날짜의 잔여(연차 또는 유대)가 부족하면 제출 전에 "남은 연차가 1일입니다. 2일을 신청할 수 없어요."라고 차단한다.
- 유대 신청은 잔여 유대가 있는 경우에만 종류 버튼이 활성화된다(잔여 0이면 비활성 + "받은 휴일대체가 없어요" 안내).
- 동일 날짜에 이미 `대기/승인` 신청이 있으면 제출 전에 차단하고 기존 신청을 보여준다.

**US-02. 종사자 신청현황 확인**
- 내 신청 목록이 대기(노랑)/승인(초록)/반려(빨강) 색+텍스트로 표시된다.
- 반려 건은 반려 사유가 항목 안에 바로 보인다(탭 없이).
- 승인 확정 시 목록 표기가 "연차신청(결재대기중)" → "연차"로 변경되어 승인 사실을 직관적으로 확인할 수 있다.

**US-03. 종사자 신청 취소**
- `대기` 상태인 본인 신청은 "신청 취소" 버튼으로 즉시 취소할 수 있다.
- `승인` 상태 신청은 직접 취소할 수 없고 "취소 신청"(별도 결재 건)을 생성한다.

**US-04. 관리자 결재 처리**
> 사무국장으로서, 출근 직후 밀린 신청을 한 화면에서 처리하고 싶다. 승인 시 해당일 인력에 지장이 없는지 확인하고 싶다.

인수 조건:
- 결재함 `대기` 탭에 신청이 오래된 순으로 표시된다.
- 승인: 원클릭. 반려: 반려 사유 입력이 **필수**다.
- **승인 시 저장된 관리자 서명 이미지가 결재란에 기재**된다(서명 미등록 시 최초 승인 전에 등록 유도).
- 처리 결과가 신청자에게 알림으로 전달된다.
- 같은 날짜에 여러 직원의 연차가 몰리면 목록에 "같은 날 연차 3건" 배지를 표시한다(인력 공백 사전 인지 — Phase 2의 근무표 대조 확인이 도입되기 전까지의 보조 장치. Phase 2부터는 상세 패널에 해당일 근무표 요약이 함께 표시된다).

**US-05. 2단계 결재**
- 시설 설정이 2단계인 경우: 관리자 승인 → `중간승인` 상태 → 상급 결재자(시설장) 승인 시 `승인` 확정. 각 단계 승인 시 해당 결재자의 서명이 단계별 결재란에 기재된다. 어느 단계에서든 반려되면 즉시 `반려` 종결.

**US-06. 시설장 결재선 설정**
- 설정 화면에서 결재 단계(1/2단계)와 단계별 결재자(복수 지정 시 1인 처리 방식)를 지정한다.
- 결재자 부재(퇴사·휴직) 시 대결자 지정이 가능하다.

**US-07. 감사 추적**
- 모든 신청은 생성→종결까지의 행위(누가, 언제, 무엇을)가 approval_history에 남고 수정·삭제할 수 없다.
- 마감·감사 대비를 위해 종결된 신청서를 출력용 서식(전자문서, 단계별 서명 포함)으로 조회/인쇄할 수 있다.

### 3.3 화면 흐름

**종사자 모바일 — 연차/유대 신청 (3단계)**
```
[홈] ─ "휴가 신청" 대형 버튼
  → (1/3) 날짜 선택: 월 달력, 탭하여 다중 선택. 선택된 날짜는 하단에 문장으로
          "7월 21일, 22일을 선택했어요"
          ※ Phase 2 이후: "내 근무표"에서 근무일을 직접 탭해 신청하는 진입 경로 추가
            (근무일이 아닌 날 선택 방지 — 0709 §2-4 워크플로우 반영)
  → (2/3) 종류 선택: [하루 종일 쉬기(연차)] [오전만 쉬기] [오후만 쉬기] [휴일대체로 쉬기]
          — 전면 폭 버튼, 쉬운 말 + 괄호로 공식 명칭. 유대 잔여 0이면 해당 버튼 비활성
  → (3/3) 확인: "7월 21일~22일, 연차 2일을 신청합니다. 남은 연차: 5일 → 3일"
          [신청하기] / [고치기]
  → 완료 화면: 초록 배경 + "신청 완료. 승인되면 알려드릴게요." + 진동
```

**종사자 모바일 — 신청현황**
```
[신청현황] 리스트 (최신순)
 ┌──────────────────────────────┐

**관리자 웹 — 결재함**
```

          (Phase 2 이후: 해당일 근무표 요약이 패널에 함께 표시 — 인력 지장 여부 확인)

### 3.4 상태머신 (확정 명세)

```
                    ┌──────────┐
       제출         │  대기      │──── 본인 취소 ────▶ 취소됨(종결)
  ──────────────▶  │ PENDING   │
                    └────┬─────┘
          1단계 결재선     │      2단계 결재선
     ┌────────────────┼──────────────────┐
     ▼                    ▼                  ▼
  승인 ────▶ APPROVED   반려(사유 필수) ─▶ REJECTED   1차 승인 ─▶ INTERIM_APPROVED
  (종결)                  (종결)                          │
                                              ┌─────────┴─────────┐
                                              ▼                     ▼
                                        2차 승인 ▶ APPROVED    2차 반려 ▶ REJECTED

APPROVED 이후: 신청자 "취소 신청" → 새로운 결재 건(type=cancel, 원건 참조)
              취소 신청 승인 시 원건 상태 = CANCELED_AFTER_APPROVAL, 잔여(연차/유대) 복원
```

**전이 규칙표**

| 현재 상태 | 행위 | 행위자 | 다음 상태 | 부수효과 |
|---|---|---|---|---|
| (없음) | 제출 | 종사자 본인 | PENDING | 잔여 검증(연차/유대), 결재자 알림, history 기록 |
| PENDING | 취소 | 신청자 본인 | CANCELED | 알림 불필요, history 기록 |
| PENDING | 승인 | 1차 결재자 | APPROVED 또는 INTERIM_APPROVED | 잔여 차감(APPROVED 시), 서명 기재, `request.approved` 이벤트, 신청자 알림 |
| PENDING | 반려 | 1차 결재자 | REJECTED | 반려사유 저장(필수), 신청자 알림 |
| INTERIM_APPROVED | 승인 | 2차 결재자(시설장) | APPROVED | 잔여 차감, 2차 서명 기재, 이벤트, 알림 |
| INTERIM_APPROVED | 반려 | 2차 결재자 | REJECTED | 사유 필수, 알림(1차 결재자에게도) |
| APPROVED | 취소 신청 | 신청자 | (별건 생성) | 원건은 유지, 별건 결재 진행 |

**불변 규칙**
- 종결 상태(APPROVED/REJECTED/CANCELED)에서의 직접 상태 변경은 금지. 정정은 반드시 새 결재 건으로.
- 잔여 차감 시점 = **최종 APPROVED 시점** (신청 시점 아님). 단, 신청 시점에 "예약 수량"으로 이중신청을 막는다(§3.6 D-2).
- 결재자는 본인이 신청자인 건을 처리할 수 없다(자기결재 금지) → 이 경우 자동으로 차상위/대결자에게 배정.

### 3.7 API 명세 초안 (REST)

```
POST   /api/requests                  신청 생성 (본인)
        body: { type, targetDates[], desiredShiftId?, reason?, refRequestId? }
        409: DUPLICATE_DATE | INSUFFICIENT_BALANCE
GET    /api/requests?mine=true        내 신청 목록 (종사자)
GET    /api/requests?status=PENDING   결재함 목록 (결재자 권한)
POST   /api/requests/{id}/cancel      대기 건 취소 (본인)
POST   /api/requests/{id}/approve     승인 (해당 step 결재자, 서명 기재)
POST   /api/requests/{id}/reject      반려 body: { comment(필수) }
GET    /api/requests/{id}/history     결재 이력
GET    /api/leave-balance/me          내 잔여 연차
GET    /api/substitute-holiday/me     내 잔여 유대
POST   /api/substitute-holiday/grant  유대 수동 부여 (관리자)
GET/PUT /api/settings/approval-line   결재선 설정 (시설장)
PUT    /api/settings/signature        서명 이미지 등록/변경 (결재 권한자)
GET    /api/notifications             알림 목록 / PATCH read 처리
```
- 모든 쓰기 API는 멱등키(Idempotency-Key) 지원 — 시니어 사용자의 더블탭으로 인한 중복 제출 방지.
- 승인/반려는 요청 시점 상태를 조건으로 하는 낙관적 처리(이미 종결된 건이면 409 ALREADY_FINALIZED) — 결재자 2인이 동시에 처리하는 경합 대응.

### 3.8 엣지케이스 체크리스트

1. 동시 결재 경합(관리자·시설장이 같은 건을 동시에 처리) → §3.7 낙관적 처리로 한쪽 409.
2. 결재자 퇴사/휴직 중 대기 건 존재 → 대결자 자동 승계 + 시설장 알림.
3. 연차 신청 후 부여량이 수정되어 잔여가 음수가 되는 경우 → 잔여 음수 허용하되 결재함에 경고 배지, 승인 시 확인 모달.
4. 반차 2건(오전+오후)을 같은 날 신청 → 허용하되 합산 1일 차감, 목록에 병합 표시.
5. 취소 신청이 대기 중인데 원건 대상일이 지나버림 → 취소 신청 자동 반려(사유: 대상일 경과) + 알림.
6. 오프라인 상태에서 제출 → 로컬 큐 저장, 재접속 시 전송(멱등키로 중복 방지), "전송 대기중" 상태 표시.
7. 기기 분실 → 관리자 화면에서 기기 등록 해제(원격 로그아웃).
8. 유대 잔여가 있으나 유효기간(당해 연도) 만료 임박 → 12월 초 잔여 유대 보유자에게 소멸 예정 알림.
9. 유대 부여 후 해당 공휴일 근무 기록이 정정됨 → 부여 취소는 관리자 수동(감사로그 기록), 이미 사용된 경우 경고 표시.

## 4. Phase 2 상세 스펙 — 근무표 작성 엔진 (0709 확정 수치 반영)

> v3.0에서 "v2 명세 준용"으로 두었던 수치를 본 절에 확정 기재한다. 수치는 설정 테이블로 관리하되 기본값은 아래 원문 값을 따른다.

### 4.1 월 기준근무시간

```
월 기준근무시간 = (해당 월 전체 일수 − 토·일 − 법정공휴일(대체공휴일 포함)) × 8시간
```

**기준근무시간 인정 항목:** 일반근무, 연차(반차), 유급병가, 기타휴일(교육 등), 유급휴일대체(§4.4의 공단 인정 규칙 적용)
**기준근무시간 불인정 항목:** 무급병가, 휴무, 결근, 휴직

근무자별 근무시간이 월 기준근무시간에 충족하는지 판별하고, 미충족 시 오류를 출력한다.

### 4.2 월별 적정 근무자 수 체크 — 인력배치 기준 (입소자 30명 이상 노인요양시설)

| 직종 | 배치 기준 | 비고 |
|---|---|---|
| 시설장 | 1명 | |
| 사무국장 | 1명 | 입소자 50명 이상인 경우로 한정 |
| 사회복지사 | 1명 | 입소자 100명 초과 시마다 1명 추가 |
| 간호(조무)사 | 입소자 25명당 1명 | |
| 물리치료사(또는 작업치료사) | 1명 | 입소자 100명 초과 시마다 1명 추가 |
| 요양보호사 | 입소자 2.1명당 1명 | |
| 사무원 | 1명 | 입소자 50명 이상인 경우로 한정 |
| 영양사 | 1명 | 위탁급식 이용 시 면제 |
| 조리원 | 입소자 25명당 1명 | 위탁급식 이용 시 면제 |

| 관리인 | 1명 | 입소자 50명 이상인 경우로 한정 |

**근무자 산정 방식**
- 월 기준근무시간 충족 또는 초과 시 근무자 1인으로 인정.
- 미달 시: `미달 근무자 직군별 근무시간 합산 ÷ 월 기준근무시간 = 근무인원 수`
  - 가산 산정: 소수점 이하 버림
  - 감액 산정: 소수점 둘째 자리 버림 후, 첫째 자리가 4 이하인 경우 첫째 자리도 버림

### 4.3 가산 산정 (실시간 경고 팝업의 판정 기준)

가산 기준 위반 여부는 **관리자가 설정한 목표 가산 점수** 대비로 판단한다. 입소자 수 ÷ 근무인원 수 계산은 소수점 셋째 자리에서 절사.

**① 인력배치추가 가산** — 인력배치 기준 초과 배치 + 직종별 별도 기준 충족 시
- 간호(조무)사: 추가배치 인원 1인당 입소자 수 19.0명 미만일 때 1인 산정, 1인당 **1.2점**
- 사회복지사: 배치기준 초과 인원부터 1인 산정, 1인당 **1.4점**
- 물리(작업)치료사: 배치기준 초과 인원부터 1인 산정, 1인당 **1.4점**

**② 야간직원배치 가산** — 야간(22:00~익일 06:00)에 요양보호사 또는 간호(조무)사 1명 이상 근무 시 **0.9점**
- 추가 요건: 야간근무 직원 1인당 입소자 20인 이하 / 주간(야간 제외 시간) 근무 요양보호사+간호(조무)사 수 합이 야간직원의 2배 이상
- 야간배치 인력수 = Σ(일자별 22~06시 실근무시간) ÷ 7 ÷ 급여제공일수, 소수점 이하 절사
- 주간배치 인력수 = Σ(일자별 06~22시 실근무시간 + 제12조제1항 근무시간) ÷ 14 ÷ 급여제공일수, 소수점 이하 절사

**③ 간호사배치 가산** — 간호사 1인당 **0.6점**, 입소자 50인 이상 시설은 최종 가산점수에 **0.2점** 추가

### 4.4 유급휴일대체의 공단 인정 규칙

- 유대가 발생한 **당월 기준근무시간을 초과한 시간분만** 공단 기준근무시간에 산입 인정, **최대 8시간** 한정.
  - 예: 기준 176시간인 달에 공휴일 근무로 총 182시간 20분 근무 → 6시간 20분만 인정.
- 이 규칙은 **공단 인정시간 산정에만** 사용한다. 실제 근무자는 근로기준법에 따라 연차와 동일하게 1일을 쉬고 유급휴가와 동일한 급여를 받는다(Phase 1 결재·잔여 관리는 1일 단위 — §3).
- 당해 연도만 산정(이월 없음 — D-11과 일치).

### 4.5 일별 적정 근무자 수 체크

- 팀 단위 그룹화 → 그룹별 일일 최소/최대 인원 설정 → 설정값 대비 과·부족 표시.

### 4.6 근무 패턴 프리셋

- 근무형태: 주간, 야간, 주야비(주·주·야·야·비·비 — 주간 2일, 야간 2일, 비번 2일)
- 주야비 프리셋(3조 2교대): A조 주간 2일 시작, B조 휴일 2일 시작, C조 야간 2일 시작
  - 예) A조: 주·주·야·야·휴·휴 / B조: 휴·휴·주·주·야·야 / C조: 야·야·휴·휴·주·주

### 4.7 결재 연동

- `request.approved` 이벤트 구독으로 승인된 연차·유대·근무조정을 근무표 셀에 자동 반영.
- 결재함 상세 패널에 해당일 근무표 요약을 표시해, 관리자가 "해당일 연차 사용 시 근무자 수에 지장이 없는지" 확인 후 결재하는 0709 워크플로우를 구현.

## 5. Phase 3~4 개요

### 5.1 Phase 3 — 출퇴근 (GPS)

- GPS 기반 원터치 출퇴근 태그: **지정 반경 내에서만 활성화**.
- **성능 요건: GPS 수신 및 출퇴근 처리 3초 이내.** 처리 실패/지연 시 직관적 피드백(문장 + 색상 + 진동)을 제공한다.
- 수동태그 폴백: Phase 1 결재 엔진에 `MANUAL_TAG` 유형을 추가하는 방식으로 재사용.
- 실근무시간 산정(§4.3 야간/주간 인력수 계산의 입력), 법정공휴일 근무 감지 → 유대 부여 후보 제시(확정은 관리자, D-10).

### 5.2 Phase 4 — 마감·내보내기

- 근무표 마감 워크플로우(마감 후 수정은 결재 경유).
- Excel 내보내기(마감된 근무표·출퇴근부 기준):
  1. **공단 입력용** 형식
  2. **사내 게시용 근무표** 형식
  3. 출퇴근부
