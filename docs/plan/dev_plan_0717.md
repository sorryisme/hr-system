# 요양원 근태관리 프로그램 — 개발 기획서 v3.2


## 1. 프로젝트 개요 및 타겟 정의

- **목적:** 장기요양보험 고시 기준을 준수한 정확한 근태관리 프로그램 제작 → 근무관리 업무 효율성 증진. 
- **주요 타겟:** 요양원의 관리자(사무국장·사회복지사·시설장)와 근무자(평균 60세 이상).

### 1.1 타겟 페르소나 A — 관리자 (사무국장·사회복지사) *(신규, 제품기획안 v3.2 §1)*

| 특성 | 설계 시사점 |
| --- | --- |
| 데스크톱 환경에서 작업 | 관리자 기능은 웹(데스크톱 우선). 다열 표·패널 병렬 배치 허용 |
| 고시·수가·근로기준법 지식 보유 | 공식 용어를 그대로 사용(순화 불필요). 산정 근거 수치를 화면에 노출해 검증 가능하게 |
| 전체 현황 파악이 핵심 과업 | 밀도 높은 대시보드·근무표 편집기. 요약→상세 드릴다운 구조 |
| 이벤트(위반·미결재·소멸 임박) 검증 책임 | 이벤트별 색+텍스트+배지로 직관 식별, 클릭 시 해당 상세로 즉시 이동 |

### 1.2 타겟 페르소나 B — 근무자 (베이비붐 세대 여성 근로자, 평균 60세+)

1. 시력·청력 등 신체 기능 노화 → 큰 글씨(본문 16pt+, 버튼 라벨 18pt+)·고대비(WCAG AA 4.5:1)·진동 피드백 필수.
2. 평균 학력 초졸 수준 → 쉬운 한글 용어 + 괄호 병기(예: "하루 종일 쉬기(연차)"), 문장형 안내.
3. 변화와 기술에 대한 보수적 태도 → 종이 병행 기간 허용, 3단계 이내 신청, 최초 1회 기기 등록 후 자동 로그인(C-13).
4. 육체노동자 → 짧은 조작 시간, 원터치 중심(출퇴근 태그), **화면당 1개 과업**.

> 두 페르소나는 전 Phase의 UX 판단 기준이며, §7 비기능 요구사항의 근거다. 관리자 화면(A-계열)은 페르소나 A, 종사자 모바일(B-계열)은 페르소나 B를 기준으로 판단한다.

### 1.3 사용자 역할 및 권한 *(Fact — 제품기획안 v3.2 §3 확정)*

| 역할 | 권한 |
| --- | --- |
| 시설장 | 전체 설정, 근무표 확정/마감, 결재 최종 승인, 사용자 관리 |
| 사무국장 | 전체 설정, 근무표 확정/마감, 결재 최종 승인 전까지(**시설장 전결 위임 시 최종 승인 가능**), 사용자 관리 |
| 사회복지사 | 근무표 작성·수정, **결재 1차 처리**, 내보내기 |
| 근무자 | 본인 및 본인 팀 근무표 조회, 출퇴근 태그, 휴가·근무조정 신청, 본인 신청현황 조회 |

- **개인정보 보호 원칙:** 근무자는 자기 팀 외 근무정보 조회 불가, 타인 개인정보 조회 불가. 내보내기 파일의 개인식별정보는 최소화(이름 외 연락처·주소 미포함).

## 2. 개발 로드맵 (순차 개발 전략)

### 2.1 왜 결재 시스템이 먼저인가 — 기획 관점 정리

*(v3.1 확정 유지. 제품기획안 v3.2 병합으로 근무표 엔진의 전제(근무유형 정의·상태머신·대시보드·마감결재)가 오히려 늘어나 의존성 축의 근거가 강화됨 — 기획 판단)*

| 근거 | 설명 |
| --- | --- |
| 의존성 최소 | 결재는 직원 마스터 + 인증만 있으면 독립 동작. 근무표 엔진은 고시 계산·프리셋·검증에 더해 v3.2에서 근무유형 정의(§4)·근무표 자체 상태머신·마감결재까지 전제가 확대 |
| 즉시 체감 가치 | 종이 연차신청서 → 모바일 신청 전환 순간 종사자·관리자 모두 효용 체감. 60세+ 사용자의 앱 수용성 조기 검증 |
| 데이터 축적 | 결재로 확정된 연차/유대/근무조정 데이터가 근무표 모듈의 입력값. 선행 구축 시 Phase 2가 실데이터로 시작 |
| 사용성 리스크 조기 검증 | "3단계 이내 신청" 등 시니어 UX 가설을 가장 단순한 모듈에서 먼저 실험 |

### 2.2 단계 정의

```

  - 인증: 관리자 발급 코드로 최초 1회 기기 등록 → 자동 로그인 (C-13)
  - 직원 마스터(A-5 필드: 이름, 직군, 입사일, 연차 부여 수, 근무 가능 형태, 재직 상태)
  - 팀 정의(직원 등록 시 지정, 설정에서 변경 가능)
  - 역할/권한 4종(§1.3), 시설 기본정보, 서명 이미지 등록(결재 권한자)
Phase 1. ★결재 시스템        (본 문서의 상세 기획 대상 → §3)
  - 연차/반차/유대/근무조정 신청·승인·반려, 결재선(1~3단계+전결), 결재함
  - 잔여 관리: 연차 + 유대(1일 단위) / 유대 관리대장(시간 단위, Phase 1은 수동 기입)
  - 유대 근무자 확인 서명, 전자서명 결재, 알림(인앱), 감사로그, 출력용 서식
  - 연차 소멸 임박 알림(입사일 기준 60일/30일 규칙 — C-10)
Phase 2. 근무표 작성 엔진     (§4 확정 스펙)
  - 근무표 편집기(A-2), 근무유형 정의(C-6), 프리셋(주야비 3조 2교대)
  - 월별/일별 인력 검증, 가산 3종 계산, 실시간 검증 패널, 경고 팝업
  - 근무표 상태머신(작성중→작성완료→마감결재→마감, C-5)
  - 대시보드(A-1), 종사자 내 근무표(B-3), 유대 인정시간 자동 산정
  - Phase 1 산출물(승인된 연차·유대·근무조정)의 근무표 자동 반영
Phase 3. 출퇴근 (GPS)
  - 원터치 태그(지정 반경, 3초 이내, B-2), 미태그 알림→사유 제출→확인(C-14)
  - 수동태그 폴백(→ Phase 1 결재 엔진 재사용), 지각·조기퇴근 확인
  - 실근무시간 산정(유대 관리대장 자동화 입력), 공휴일 근무 감지→유대 후보 제시
Phase 4. 마감·내보내기
  - Excel: 공단입력용 / 사내 게시용 근무표 / 출퇴근부 / 인력산정 요약 (C-9)

Phase 5. (백로그) 근로기준법 검토 엔진
  - 노동법 위반 검토·예방, 세무사 협업 급여산정자료 export, 연차 자동산정
```

### 2.3 단계 간 인터페이스 계약 (결재를 독립 개발하기 위한 장치)

Phase 1은 후속 모듈이 없어도 완결 동작해야 한다. 이를 위해:

- **이벤트 발행 방식:** ① 최종 승인 시 `request.approved` ② **1차(사회복지사) 승인 시 `request.step_approved`** *(신설 — C-2)* 를 발행만 한다. Phase 1 구독자는 알림 모듈뿐. Phase 2에서 근무표 반영 모듈이 추가 구독: `step_approved` → 근무표 가반영(글자만), `approved` → 확정 반영(셀 색칠) + 잔여 차감 표시. → 결재 코드는 이후 수정 불필요.
- **잔여(연차·유대 1일 단위) 관리는 Phase 1에 포함:** 근무표 없이도 부여/사용/잔여가 계산되도록 employee 마스터에 귀속.
- **유대 관리대장(시간 단위)은 Phase 1에서 "수동 기입 + 서명"까지:** 월기준근무시간·실근무시간을 관리자가 수기 입력하고 이월가능시간을 직접 기재한다(D-15). 자동 산정은 Phase 2(월기준시간 계산), 실근무시간 자동 입력은 Phase 3(GPS). 근무자 확인 서명 요청·수신은 Phase 1부터 동작.
- **근무조정 신청은 Phase 1에서 "기록·결재"까지만:** 실제 근무표 셀 변경은 Phase 2에서 이벤트 구독으로 구현. 그 사이 기간에는 승인 결과를 관리자가 수기 근무표에 반영한다.
- **연차 소멸 임박 알림은 Phase 1에서 동작:** 입력이 leave_balance와 입사일뿐이므로 근무표 불필요. 대시보드 카드(A-1)는 Phase 2에서 동일 로직을 재사용한다.

### 2.4 Phase 1 성공 지표 (기획 KPI) *(v3.1 유지)*

- 종사자 신청 완료율(신청 시작 → 제출) ≥ 90%
- 신청 1건 소요 시간 ≤ 60초 (시니어 사용자 실측)
- 종이 신청서 병행 비율: 도입 2개월 내 20% 이하
- 결재 처리 리드타임(신청 → 최종 승인/반려) 중앙값 ≤ 24시간 ※ 결재선이 최대 3단계로 늘어난 점을 감안해 파일럿에서 단계별 리드타임을 분해 측정한다(기획 판단)

## 3. Phase 1 상세 기획 — 결재 시스템

### 3.1 범위 정의

**포함**

- 신청 유형(enum): `ANNUAL`(연차), `HALF_AM`(오전반차), `HALF_PM`(오후반차), `SUBSTITUTE_HOLIDAY`(유급휴일대체), `SHIFT_CHANGE`(근무조정), `CANCEL`(승인 후 취소)
- 결재선: **1~3단계**, 시설 설정으로 선택. 표준 3단계 = 사회복지사(1차) → 사무국장(2차) → 시설장(최종). **전결:** 시설장이 사무국장에게 위임 시 2차 승인으로 최종 확정(D-13)
- 결재함(관리자 웹, A-3), 신청·현황(종사자 모바일, B-4)
- 잔여 관리: 연차(부여/사용/잔여, 최종 승인 시 차감) + 유대 1일 단위(부여/사용/잔여, 당해 연도 소멸)
- **유대 관리대장(A-4, 시간 단위):** 이름·근무일(유급휴일)·근무 구분(주간/야간)·사용예정일자·사용 구분·월기준근무시간·실근무시간·이월가능시간(분, 최대 480). Phase 1은 관리자 수동 기입. **근무자 확인 서명 요청→서명** 워크플로우 포함(감사용 관리대장)
- **전자서명:** 각 단계 승인 시 해당 결재자의 저장된 서명 이미지가 단계별 결재란에 기재(출력용 서식 포함)
- 알림(인앱 확정, 푸시/알림톡은 D-7 결정 대기), 감사로그, 신청서 출력용 서식(PDF 뷰)
- 연차 소멸 임박 알림: 입사일 도래 60일 전 잔여 3일 이상(노랑/사용 필요), 30일 전 잔여 존재(빨강/조치 필요) — 관리자 대상(C-10)

**제외 (후속 단계)**

- 근무표 자동 반영·가반영 표시(Phase 2 — 이벤트 구독으로 구현, §2.3)
- 유대 인정시간 자동 산정(Phase 2) 및 실근무시간 자동 입력(Phase 3)
- 미태그 사유 제출·수동 출퇴근 태그 결재(Phase 3 — 결재 엔진에 유형 추가만으로 재사용)
- **병가·결근:** 신청·결재 유형이 아님. Phase 2 근무표에서 관리자 직접 입력으로 관리(D-18)
- 기타 휴가 유형(경조 등 — 유형 확장 구조만 확보)

### 3.2 사용자 스토리 및 인수 조건

**US-01. 종사자 연차/유대/근무조정 신청**

> 요양보호사로서, 다음 주 연차를 휴대폰에서 신청하고 싶다. 종이 신청서를 쓰고 사무실까지 가지 않기 위해서다.

인수 조건:

- Given 로그인한 종사자가 / When 날짜 선택 → 종류 선택 → "신청하기" 3단계를 완료하면 / Then 신청이 `대기` 상태로 생성되고 1차 결재자에게 알림이 간다.
- **사유 입력: 연차·반차·유대는 선택(강제 금지 — 페르소나 B), 근무조정은 필수(D-14).** 근무조정 화면에는 "바꾸려는 이유를 적어주세요 (예: 병원 예약)" 문장형 안내를 표시한다.
- 선택한 날짜의 잔여(연차 또는 유대)가 부족하면 제출 전에 "남은 연차가 1일입니다. 2일을 신청할 수 없어요."라고 차단한다.
- 유대 신청은 잔여 유대가 있는 경우에만 종류 버튼이 활성화된다(잔여 0이면 비활성 + "받은 휴일대체가 없어요").
- 동일 날짜에 이미 `대기/승인` 신청이 있으면 제출 전에 차단하고 기존 신청을 보여준다.
- (Phase 2 이후) 신청 진입 경로에 "내 근무표에서 근무일 선택"이 추가된다 — 근무일이 아닌 날 선택 방지.

**US-02. 종사자 신청현황 확인** *(v3.1 유지)*

- 대기(노랑)/승인(초록)/반려(빨강)를 색+텍스트로 표시. 반려 사유는 항목 안에 바로 노출(탭 없이).
- 최종 승인 시 표기가 "연차신청(결재대기중)" → "연차"로 변경된다.

**US-03. 종사자 신청 취소** *(v3.1 유지)*

- `대기`·`중간승인` 상태의 본인 신청은 "신청 취소"로 즉시 취소. `승인` 확정 건은 "취소 신청"(별도 결재 건, type=CANCEL) 생성.

**US-04. 1차 결재자(사회복지사) 결재 처리**

> 사회복지사로서, 밀린 신청을 한 화면에서 1차 처리하고 싶다. 승인 시 해당일 인력에 지장이 없는지 확인하고 싶다.

인수 조건:

- 결재함 `대기` 탭에 오래된 순 표시. 승인: 원클릭(서명 기재). 반려: 사유 입력 **필수**.
- 1차 승인 시 `중간승인` 상태로 전이하고 다음 단계 결재자에게 알림. `request.step_approved` 이벤트 발행(Phase 2부터 근무표 가반영 — 글자만).
- 같은 날짜에 여러 직원의 신청이 몰리면 "같은 날 연차 3건" 배지 표시(Phase 2부터는 상세 패널에 해당일 근무표 요약 병행).

**US-05. 2·3차 결재(사무국장·시설장) 및 전결**

- 표준 3단계: 사회복지사 승인 → `중간승인(1차 완료)` → 사무국장 승인 → `중간승인(2차 완료)` → 시설장 승인 → `승인` 확정.
- **전결 설정 시:** 사무국장 승인이 곧 최종 확정(`승인`). 결재란에는 "전결" 표기와 사무국장 서명이 최종란에 기재된다(감사 시 위임 사실 식별 — D-13).
- 각 단계 승인 시 해당 결재자 서명이 단계별 결재란에 기재. 어느 단계에서든 반려 시 즉시 `반려` 종결(신청자 + 선행 승인자에게 알림).

**US-06. 결재선 설정(시설장)**

- 결재 단계 수(1/2/3단계)와 단계별 결재자(역할 또는 개인 지정)를 설정. **전결 위임 on/off**(대상: 사무국장).
- 결재자 부재(퇴사·휴직) 시 대결자 지정 가능. 자기결재 금지 유지(D-6).

**US-07. 감사 추적** *(v3.1 유지)*

- 모든 신청의 생성→종결 행위가 approval_history에 append-only로 남는다. 종결된 신청서는 단계별 서명이 포함된 출력용 서식으로 조회·인쇄 가능.

**US-08. 관리자 유대 관리대장 기입 및 서명 요청** *(신설 — C-4)*

> 사무국장으로서, 공휴일 근무자의 유대 발생 내역을 대장에 기록하고 본인 확인 서명을 받아 감사에 대비하고 싶다.

인수 조건:

- Given 법정공휴일 근무 사실을 확인한 관리자가 / When 대장에 [근무자, 근무일, 근무 구분, 월기준근무시간, 실근무시간, 이월가능시간(분)]을 기입하고 저장하면 / Then 유대 잔여(1일 단위)가 +1 부여되고 대장 행이 생성된다(D-15).
- 이월가능시간은 480분(8시간)을 초과 입력할 수 없다(공단 인정 상한 — §4.4, Fact: 제품기획안 v3.2 §4.1.마).
- "서명 요청 보내기" 실행 시 해당 근무자에게 알림이 가고, 대장 행 상태가 `서명 대기`가 된다.
- 사용예정일자는 Phase 1에서 수동 기재, Phase 2부터 근무표 입력 시 자동 연동.

**US-09. 근무자 유대 확인 서명** *(신설 — C-4)*

> 요양보호사로서, 내가 공휴일에 근무해 받은 휴일대체 내역이 맞는지 확인하고 서명하고 싶다.

인수 조건:

- 알림 수신 → 확인 화면에 "10월 3일(개천절)에 근무하셔서 쉬는 날 1일을 받았어요"를 문장형으로 표시(페르소나 B 언어).
- 서명 완료 시 대장 행 상태 `서명 완료`, 서명은 시점 사본으로 대장에 보존(수정 불가).
- **서명 수단은 [결정 대기](D-16):** ⓐ 화면 손가락 서명(draw) vs ⓑ 사전 등록 서명 이미지 + "확인" 탭. 트레이드오프는 §3.6 참조.

### 3.3 화면 흐름

**종사자 모바일 — 연차/유대 신청 (3단계)** *(v3.1 유지 + 근무조정 분기 추가)*

```
[홈] ─ "휴가 신청" 대형 버튼
  → (1/3) 날짜 선택: 월 달력, 탭하여 다중 선택. "7월 21일, 22일을 선택했어요"
  → (2/3) 종류 선택: [하루 종일 쉬기(연차)] [오전만 쉬기] [오후만 쉬기] [휴일대체로 쉬기]
          — 전면 폭 버튼. 유대 잔여 0이면 해당 버튼 비활성
  → (3/3) 확인: "7월 21일~22일, 연차 2일을 신청합니다. 남은 연차: 5일 → 3일"
          [신청하기] / [고치기]
  → 완료 화면: 초록 배경 + "신청 완료. 승인되면 알려드릴게요." + 진동

[홈] ─ "근무 바꾸기 신청" 버튼
  → (1/3) 바꿀 날짜 선택 → (2/3) 원하는 근무 선택 + 이유 입력(필수, 문장형 안내)
  → (3/3) 확인 → 완료
```

**종사자 모바일 — 유대 확인 서명** *(신설)*

```
  → 확인 화면: "10월 3일(개천절)에 근무하셔서 쉬는 날 1일을 받았어요."

  → [확인하고 서명하기] → 서명 → 완료(초록 + 진동)
```

### 3.4 상태머신 (확정 명세)

결재선이 1~3단계 가변이므로 `중간승인` 상태에 **current_step**(현재 완료된 단계 수)을 병기한다. 상태 골격은 v3.1을 유지한다(최신안에 상태머신 변경 지시 없음).

```
                     ┌──────────┐
        제출          │  대기      │──── 본인 취소 ────▶ CANCELED(종결)
   ──────────────▶  │ PENDING   │
                     └────┬─────┘
                          │ 1차 승인(사회복지사)                반려(사유 필수, 모든 단계 공통)
                          ▼                                      ──▶ REJECTED(종결)
                 INTERIM_APPROVED (current_step=1)
                          │ 2차 승인(사무국장)
              ┌───────────┴───────────┐
              │ 전결 설정 ON            │ 전결 설정 OFF
              ▼                        ▼
         APPROVED(종결, "전결" 표기)   INTERIM_APPROVED (current_step=2)
                                       │ 최종 승인(시설장)
                                       ▼
                                  APPROVED(종결)

※ 결재선 1단계 설정 시: PENDING → (1차 승인) → APPROVED
※ INTERIM_APPROVED 상태에서 신청자 취소 허용(아직 미확정) → CANCELED, 선행 승인자 알림
APPROVED 이후: 신청자 "취소 신청" → 새 결재 건(type=CANCEL, 원건 참조)
              취소 신청 승인 시 원건 = CANCELED_AFTER_APPROVAL, 잔여(연차/유대) 복원
```

**전이 규칙표**

| 현재 상태 | 행위 | 행위자 | 다음 상태 | 부수효과 |
| --- | --- | --- | --- | --- |
| (없음) | 제출 | 종사자 본인 | PENDING | 잔여 검증·reserved 가산, 1차 결재자 알림, history 기록 |
| PENDING | 취소 | 신청자 본인 | CANCELED | reserved 해제, history 기록 |
| PENDING | 승인 | 1차 결재자 | INTERIM_APPROVED(step=1) 또는 APPROVED(1단계 설정 시) | 서명 기재, `step_approved` 이벤트, 다음 결재자 알림(최종이면 잔여 차감 + `approved` 이벤트 + 신청자 알림) |
| PENDING | 반려 | 1차 결재자 | REJECTED | 반려사유 저장(필수), reserved 해제, 신청자 알림 |
| INTERIM_APPROVED(1) | 승인 | 2차 결재자(사무국장) | APPROVED(전결 ON) 또는 INTERIM_APPROVED(2) | 서명 기재. 전결 시: "전결" 표기, 잔여 차감, `approved` 이벤트, 알림 / 비전결 시: 시설장 알림 |
| INTERIM_APPROVED(2) | 승인 | 최종 결재자(시설장) | APPROVED | 잔여 차감, 최종 서명 기재, `approved` 이벤트, 신청자 알림 |
| INTERIM_APPROVED(1·2) | 반려 | 해당 단계 결재자 | REJECTED | 사유 필수, reserved 해제, 신청자 + 선행 승인자 알림 |
| INTERIM_APPROVED(1·2) | 취소 | 신청자 본인 | CANCELED | reserved 해제, 선행 승인자 알림, history 기록 |
| APPROVED | 취소 신청 | 신청자 | (별건 생성) | 원건 유지, 별건 결재 진행 |

**불변 규칙**

- 종결 상태(APPROVED/REJECTED/CANCELED/CANCELED_AFTER_APPROVAL)에서의 직접 상태 변경 금지. 정정은 반드시 새 결재 건으로.
- 잔여 차감 시점 = **최종 APPROVED 시점**. 신청 시점에는 reserved로 이중신청만 차단(D-2).
- 자기결재 금지: 결재자가 신청자인 건은 자동으로 차상위/대결자에게 배정(D-6). 전결 상태에서 사무국장 본인 신청 건은 시설장이 처리.

### 3.7 API 명세 초안 (REST)

```
POST   /api/requests                      신청 생성 (본인)
        body: { type, targetDates[], desiredShiftId?, reason?, refRequestId? }
        400: REASON_REQUIRED (SHIFT_CHANGE에 reason 누락)
        409: DUPLICATE_DATE | INSUFFICIENT_BALANCE
GET    /api/requests?mine=true            내 신청 목록 (종사자)
GET    /api/requests?status=PENDING       결재함 목록 (결재자 권한 — 본인 단계 대기 건)
POST   /api/requests/{id}/cancel          대기·중간승인 건 취소 (본인)
POST   /api/requests/{id}/approve         해당 단계 승인 (서명 기재, 전결 규칙 적용)
        409: ALREADY_FINALIZED | NOT_YOUR_STEP | SELF_APPROVAL_FORBIDDEN
POST   /api/requests/{id}/reject          반려 body: { comment(필수) }
GET    /api/requests/{id}/history         결재 이력

GET    /api/leave-balance/me              내 잔여 연차
GET    /api/substitute-holiday/me         내 잔여 유대(1일 단위) + 내 대장 요약

POST   /api/sh-ledger                     유대 대장 행 생성 (관리자) — balance +1 연동
        body: { employeeId, workedHolidayDate, workedShift, plannedUseDate?,
                baseMonthlyHours, actualWorkedHours, carryableMinutes(0..480) }
        400: CARRYABLE_EXCEEDS_LIMIT
GET    /api/sh-ledger?year=&employeeId=   대장 목록/감사용 출력 데이터
PATCH  /api/sh-ledger/{id}                행 정정 (관리자, 사유 필수 — SIGNED면 서명 무효화+재요청)
POST   /api/sh-ledger/{id}/request-sign   서명 요청 발송 (관리자)
POST   /api/sh-ledger/{id}/sign           근무자 서명 제출 (본인)
        409: ALREADY_SIGNED

GET/PUT /api/settings/approval-line       결재선 설정: 단계 수, 단계별 결재자, 전결, 대결자 (시설장)
PUT    /api/settings/signature            서명 이미지 등록/변경 (결재 권한자)
GET    /api/notifications                 알림 목록 / PATCH read 처리
```

- 모든 쓰기 API는 멱등키(Idempotency-Key) 지원 — 페르소나 B의 더블탭 중복 제출 방지.
- 승인/반려/서명은 요청 시점 상태를 조건으로 하는 낙관적 처리(종결·처리된 건이면 409) — 결재자 2인 동시 처리, 전결·비전결 경합 대응.
- 인증·API 크리덴셜은 코드에 하드코딩하지 않고 사내 시크릿 관리 솔루션으로 주입한다(보안 규정).

### 3.8 엣지케이스 체크리스트

1. 동시 결재 경합(같은 단계 결재자 2인 또는 전결·최종 경합) → §3.7 낙관적 처리로 한쪽 409.
2. 결재자 퇴사/휴직 중 대기 건 → 대결자 자동 승계 + 시설장 알림. 3단계 전원 부재 시 시설장 직권 처리 경로 제공.
3. 신청 후 부여량 수정으로 잔여 음수 → 허용하되 결재함 경고 배지 + 승인 시 확인 모달.
4. 반차 2건(오전+오후) 같은 날 신청 → 허용, 합산 1일 차감, 목록 병합 표시.
5. 취소 신청 대기 중 원건 대상일 경과 → 자동 반려(사유: 대상일 경과) + 알림.
6. 오프라인 제출 → 로컬 큐 저장, 재접속 시 전송(멱등키), "전송 대기중" 표시.
7. 기기 분실 → 관리자 화면에서 기기 등록 해제(원격 로그아웃). 재등록은 관리자 발급 코드로만.
8. 유대 잔여의 연말 소멸 임박 → 12월 초 보유자에게 소멸 예정 알림.
9. 유대 대장 정정(공휴일 근무 기록 오류) → 관리자 정정 + 사유 기록. balance 사용 전이면 -1 회수, 사용 후면 경고 표시. SIGNED 행은 서명 무효화 + 재서명 요청 자동 발송.
10. 서명 요청 후 장기 미서명 → 7일 경과 시 근무자 재알림 + 관리자 대시보드 배지(감사 공백 방지).
11. 중간승인 상태에서 신청자 취소 → 허용(§3.4), 선행 승인자에게 취소 알림(이미 서명한 사실은 history에 유지).
12. 전결 설정 변경 중 진행 건 → 신청 "제출 시점"의 결재선 스냅샷을 따른다(중도 변경 비소급).
13. 연차 소멸 임박(60일/30일) 판정일에 대상자 다수 → 관리자 알림은 1일 1회 집계 발송(알림 폭주 방지).

## 4. Phase 2 상세 스펙 — 근무표 작성 엔진

> 고시 수치는 v3.1 확정값과 제품기획안 v3.2 기재값의 **상호 일치를 확인**하여 유지한다(V-1, Fact). 고시 원문 파일은 미첨부 상태이므로 "원문 대조 완료" 표기는 하지 않는다. 수치는 설정 테이블(§4.10 A-6)로 관리하되 기본값은 아래 기재 값을 따른다.

### 4.1 월 기준근무시간과 인정/불인정 항목

```
월 기준근무시간 = (해당 월 전체 일수 − 토·일 − 법정공휴일(대체공휴일 포함)) × 8시간
```

- **용어 통일(기획 판단):** 제품기획안 §2 용어 정의의 "공휴일"과 §4의 "법정공휴일(대체공휴일 포함)"은 동일 개념으로 보고 후자로 통일한다. 공휴일 캘린더는 「관공서의 공휴일에 관한 규정」 기반 연도별 데이터를 설정으로 관리한다(V-4 — 출처 확정 필요).
- **기준근무시간 인정:** 일반근무, 연차(반차), 유급병가, 기타휴일(교육 등), 유급휴일대체(공단 인정시간 규칙 §4.4 적용)
- **기준근무시간 불인정:** 무급병가, 휴무, 결근, 휴직 (→ 병가·결근의 입력 방식은 D-18)
- 근무자별 근무시간이 월 기준근무시간에 충족하는지 판별하고, 미충족 시 오류를 출력한다. 유형별 인정시간은 §4.7 근무유형 정의 값을 그대로 합산한다(야간(주야비)=9시간 40분 등).

### 4.3 가산 산정 (실시간 경고 팝업의 판정 기준)

가산 기준 위반 여부는 **관리자가 설정한 목표 가산 점수** 대비로 판단한다(A-6). 입소자 수 ÷ 근무인원 수 계산은 소수점 셋째 자리에서 절사.

**① 인력배치추가 가산** — 인력배치 기준 초과 배치 + 직종별 별도 기준 충족 시

- 간호(조무)사: 추가배치 인원 1인당 입소자 수 19.0명 미만일 때 1인 산정, 1인당 **1.2점**
- 사회복지사: 배치기준 초과 인원부터 1인 산정, 1인당 **1.4점**
- 물리(작업)치료사: 배치기준 초과 인원부터 1인 산정, 1인당 **1.4점**

**② 야간직원배치 가산** — 야간(22:00~익일 06:00)에 요양보호사 또는 간호(조무)사 1명 이상 근무 시 **0.9점**

- 추가 요건: 야간근무 직원 1인당 입소자 20인 이하 / 주간(야간 제외 시간) 근무 요양보호사+간호(조무)사 수 합이 야간직원의 2배 이상
- 야간배치 인력수 = Σ(일자별 22~06시 실근무시간) ÷ 7 ÷ 급여제공일수, 소수점 이하 절사
- 주간배치 인력수 = Σ(일자별 06~22시 실근무시간 + 제12조제1항 근무시간) ÷ 14 ÷ 급여제공일수, 소수점 이하 절사
- ※ 실근무시간은 Phase 3(GPS) 전까지 근무표 계획 시간으로 대체 산정하고 화면에 "계획 기준 추정치" 라벨을 표시한다(기획 판단 — 미검증 수치를 확정치처럼 보이지 않게).

**③ 간호사배치 가산** — 간호사 1인당 **0.6점**, 입소자 50인 이상 시설은 최종 가산점수에 **0.2점** 추가

### 4.4 유급휴일대체의 공단 인정 규칙 — 관리대장(ledger) 자동 산정 연동

- 유대가 발생한 **당월 기준근무시간을 초과한 시간분만** 공단 기준근무시간에 산입 인정, **최대 8시간(480분)** 한정.
    - 예: 기준 176시간인 달에 공휴일 근무로 총 182시간 20분 근무 → 6시간 20분만 인정.
- 이 규칙은 **공단 인정시간 산정에만** 사용한다. 실제 근무자는 근로기준법에 따라 연차와 동일하게 1일을 쉬고 유급휴가와 동일한 급여를 받는다(사용 트랙은 1일 단위 — D-15).
- 당해 연도만 산정, 이월 없음(D-11).
- **Phase 2 자동화:** `carryable_minutes = clamp(실근무시간 − 월기준근무시간, 0, 480)`을 자동 계산해 ledger에 기재. base_monthly_hours는 §4.1 계산값 자동 입력. (실근무시간 자동 입력은 Phase 3)
- **비소급 원칙:** Phase 1에서 수동 기입·서명 완료된 대장 행은 재계산하지 않는다(서명된 감사 기록 보존). 자동 산정은 Phase 2 전환 후 신규 행부터 적용.
- 근무표 셀 표기 "유(인정시간,분)"은 **근무표 편집기 화면에서만** 표시한다(제품기획안 A-2 원문 — 종사자 화면·출력물에는 "유"만).

### 4.5 일별 적정 근무자 수 체크

- 팀 단위 그룹화 → 그룹별 일일 최소/최대 인원 설정(A-6) → 설정값 대비 과·부족 표시(달력 미니맵 하이라이트).

### 4.6 근무 패턴 프리셋

### 4.8 근무표 편집기(A-2)와 근무표 상태머신

**레이아웃·입력**

- 세로축 = 직원(팀별 그룹핑, 팀은 직원 등록 시 또는 설정에서 변경), 가로축 = 해당 월 일자.
- 셀 클릭 → 근무유형 선택 팝오버. 드래그로 다중 셀 일괄 입력. 직원 행 우클릭 → "프리셋 적용"(패턴 + 시작일 + 적용 기간).

**실시간 검증 패널(우측 고정)** — 편집할 때마다 재계산

- 월별 인력산정 결과(직군별 환산 인원 vs 법정 기준, §4.2)
- 일별 주/야 인원 미달일 하이라이트(달력 미니맵, §4.5)
- 가산 예상 점수(인력추가/야간/간호사 각각, §4.3) vs 목표 점수

**저장·마감 시 위반 처리(D-19 확정)**

- 저장 시 위반 존재 → 위반 항목 목록 팝업 + [그래도 저장](임시저장만 허용) / [돌아가서 수정].
- **마감은 위반 존재 시 원칙 차단.** 단 사무국장/시설장 권한자가 **사유를 입력하면 강행 마감 가능**하며, 강행 사실·사유·당시 위반 목록이 로그에 기록된다.
- 작성(저장)·수정·마감 모두 로그 기록: 작성자, 일시, 변경사항.

**근무표 상태머신**

```
DRAFT(작성중) ──작성 완료──▶ COMPLETED(작성완료) ──마감 상신──▶ CLOSING_APPROVAL(마감결재)
                                                                    │
                                              반려 ◀────────────────┤ 승인
                                              (DRAFT로 복귀)          ▼
                                                              CLOSED(마감)
```

| 현재 상태 | 행위 | 행위자 | 다음 상태 | 부수효과 |
| --- | --- | --- | --- | --- |
| DRAFT | 작성 완료 | 사회복지사 이상 | COMPLETED | 검증 패널 결과 스냅샷 저장, 로그 |
| COMPLETED | 셀 수정 | 사회복지사 이상 | DRAFT | 로그(변경사항) |
| COMPLETED | 마감 상신 | 사회복지사 | CLOSING_APPROVAL | 마감 결재자(사무국장/시설장) 알림 |
| CLOSING_APPROVAL | 승인(마감) | 사무국장 또는 시설장 | CLOSED | 위반 존재 시 사유 필수(D-19), 로그, 근무자 공지 알림 |
| CLOSING_APPROVAL | 반려 | 사무국장 또는 시설장 | DRAFT | 반려 사유 필수, 사회복지사 알림 |
| CLOSED | (직접 수정 금지) | — | — | 수정은 휴가·근무조정 **결재 경유**로만(§3 결재 엔진 재사용) |

- 불변 규칙: CLOSED 상태의 셀 직접 변경 금지. 승인된 결재 건의 이벤트 구독으로만 반영되며 모든 반영은 로그에 남는다.

### 4.10 결재·Phase 1 연동 및 설정(A-6)

- **결재 연동:** `request.step_approved`(1차 승인) 구독 → 근무표 **가반영(글자만)** / `request.approved`(최종) 구독 → **확정 반영(셀 색칠)** + 잔여 차감 표시. 결재함 상세 패널에 해당일 근무표 요약 병행 표시(관리자가 인력 지장 여부 확인 후 결재하는 워크플로우).
- **종사자 내 근무표(B-3):** 기준일 −2일~+2일을 좌우 스와이프 + 화면에 보이는 ◀▶ 버튼으로 이동(D-17). 같은 팀 근무는 본인보다 낮은 투명도로 상하 배치. 월 근무표는 별도 화면(팀원 근무는 **이름만** 표시 — §1.3 개인정보 최소 노출). 근무일 탭 → 휴가 신청 진입 경로(§3.2 US-01).
- **유대 관리대장(A-4) 자동화:** 근무표에 유대 입력 시 사용예정일자 자동 연동. 인정시간 자동 산정은 §4.4.
- **설정(A-6):**
    - 시설 정보: 입소 정원, 월별 현원(입소자 수), 적용 배치기준(**2.1:1 / 2.3:1 선택** — V-2), 위탁급식/위탁세탁 여부(영양사·조리원·위생원 면제 판단)
    - 고시 파라미터: 월 기준시간 산식 요소, 각 가산 점수·조건값(기본값 = §4.2~4.3 원문 값)
    - 일별 적정 인원: 직군별 주간/야간 최소·최대
    - 가산 목표: 목표 가산 점수
    - 출퇴근(Phase 3): 사업장 GPS 좌표, 허용 반경(m), 태그 허용 시간 여유(교대 전후 n분), 관리자 호출 전화번호
    - 근무유형 정의: 유형별 시작/종료 시각, 휴게시간(분), 야간 여부(기본값 = §4.7)

## 5. Phase 3~4 개요

### 5.1 Phase 3 — 출퇴근 (GPS)

- **홈 화면(B-2):** 화면 70% 이상의 단일 대형 버튼, 상태에 따라 "출근하기"/"퇴근하기" 자동 전환. 버튼 아래 오늘 근무를 한 문장으로("오늘은 야간 근무입니다 · 17:50~다음날 09:00").
- 태그 성공: 전체 화면 초록 + "출근 완료 · 오후 9시 52분" + 진동. 실패: 원인을 쉬운 말로("요양원에서 너무 멀리 있어요. 건물 근처에서 다시 눌러주세요.") + **관리자 호출 전화 버튼**(번호는 A-6 시설 설정값 — C-11).
- **성능 요건: GPS 수신 및 출퇴근 처리 3초 이내**(N-9). 실패·지연 시 문장+색상+진동 피드백.
- GPS 미수신/권한 거부 폴백: 수동 태그 요청 → 관리자 승인 큐. Phase 1 결재 엔진에 `MANUAL_TAG` 유형 추가로 재사용.
- **미태그 워크플로우(C-14):** 관리자가 미태그자 확인·알림 전송 → 근무자가 사유 기재 후 제출(결재 엔진 재사용) → 승인 시 근태 기록 수정 반영 → 근무자가 수정된 현황 확인.
- 지각·조기퇴근 확인 및 조치(관리자), 태그 허용 시간 여유는 교대 전후 n분 설정(A-6).
- 실근무시간 산정 → §4.3 야간/주간 인력수 계산 입력 + §4.4 ledger의 actual_worked_hours 자동화.
- 법정공휴일 근무 감지 → 유대 부여 **후보 제시**(확정·대장 기입은 관리자 — D-10).

### 5.2 Phase 4 — 마감·내보내기

- 근무표 마감 워크플로우는 §4.8 상태머신을 따른다(마감 후 수정은 결재 경유).

## 8. 이 문서에서 확정한 사항 요약

1. 개발 순서 유지: 공통기반 → **결재** → 근무표 → 출퇴근 → 마감/내보내기 → (백로그) 근로기준법 엔진. 병합 원칙 = 충돌 시 최신안(제품기획안 v3.2) 우선.
2. **결재선 3역할(사회복지사→사무국장→시설장)·전결** 및 상태머신·전이규칙·데이터모델·API 확정 (§3.4~3.7, D-13).
3. **유대 이중 트랙 확정:** 사용=1일 결재(balance), 공단 인정=시간 단위 관리대장(ledger, 최대 480분) + 근무자 확인 서명 워크플로우 (D-15, §3.5, §4.4).
4. 정책 D-1~D-19 중 **D-7(알림 채널)·D-16(근무자 서명 수단)만 결정 대기** — 파일럿(S5) 전 확정.
5. Phase 2 고시 수치(인력배치·가산 3종·월 기준시간·인정/불인정·프리셋) 및 **근무유형 정의(§4.7)·근무표 상태머신(§4.8)·대시보드(§4.9)** 본문 확정.
6. 마감 시 위반 처리 확정: 원칙 차단 + 권한자 사유 입력 후 강행 가능 + 로그 (D-19).
7. 내보내기 산출물 확정: Excel 4종(공단입력용/사내 게시용/출퇴근부/인력산정 요약) + PDF 보고서 (§5.2).
8. 비기능 요구 N-1~N-12를 페르소나 특성으로 소급 가능하게 명문화 (§7).
9. 결재 엔진은 유형 확장형: Phase 3 수동태그(MANUAL_TAG)·미태그 사유 제출, 향후 휴가 유형 추가에 재사용.
10. **원문 확인 필요(추정치 미기재):** V-2 배치기준 2.3:1 유예 적용 조건 / V-3 연차 총 상한 25일(근로기준법 제60조 대조) / V-4 공휴일 캘린더 출처. 확인 시까지 해당 항목은 본문에 [원문 확인 필요]로 유지.
11. 보완 예정 기록: 대시보드 연차 소멸 판정(§4.9 ⑥)은 입사일 기준 운영 전제 — 회계연도 기준 시설 지원 여부는 파일럿 후 재검토.
